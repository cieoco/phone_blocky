# 中央音效台

一台 PC 接喇叭，同時接收 A／B 兩塊裁判板的事件。Python 負責區網連線，HTML／JavaScript 使用瀏覽器 Web Audio 播放本機 WAV；Python 只使用標準函式庫，無須 pip 安裝或雲端服務。

## 啟動

1. PC 安裝 Python 3.10 以上，並能開啟兩塊裁判板的 STA IP。兩板可連不同基地台，但網路必須互通；中央台接受私有 IPv4（10.x、172.16–31.x、192.168.x），HTTP port 80。
2. 兩塊裁判板更新 `esp32dev_referee` 韌體與 `uploadfs`，重新整理各裁判操作頁。學生板不需因本次音效修改而更新。
3. 在本機 `referee_data/audio/` 放入 `start.wav`、`resume.wav`、`end.wav`、`abort.wav`。這些檔案不進版控；repo 不附音檔、不自動下載。只用中央台播放時，不必把音檔放到裁判板。
4. 雙擊本資料夾的 `run.bat`，瀏覽器會開 `http://127.0.0.1:8765/`。保留 Python 視窗。
5. 填入 A／B 的裁判 IP 及各自的**裁判操作密碼**（不是路由器密碼）。只用一場可留空另一欄。
6. 可先按各場「試播」，確認喇叭與音量；再按「啟用中央音效」。兩場顯示「中央播放中」後，裁判原操作頁會自動停止本機播放。

也可由終端執行：

```powershell
python tools/central_audio/server.py --open
```

音檔在其他本機資料夾時：

```powershell
python tools/central_audio/server.py --open --audio-dir "C:\match-audio"
```

預設 8765 埠已占用時可加 `--port 8766`。保留中央網頁、保持電腦清醒，建議讓此頁留在前景；關閉網頁或 Python 視窗即停止服務。音量調整不代表能偵測實體喇叭是否接好。

## 自動接管與離線

- 中央音效播放權與裁判操作權分開。裁判仍各自按開始、暫停、繼續、停止；中央端不能發出比賽控制命令。
- 瀏覽器必須先啟用音訊且四檔皆載入成功才送心跳。只是啟動 Python／開頁面不會搶播放權。
- 每塊裁判板只接受一個中央頁面持有播放權。請只開一個中央頁；第二頁會顯示另一台持有播放權。
- 依使用者選擇，A／B 事件立即播放，允許兩場音效重疊，不排隊延後。每場有獨立事件序號與播放節點，互不取消；畫面標示哪一場播放了什麼。
- 心跳逾期 5 秒後，裁判頁顯示中央離線，**不自動恢復本機聲音**。裁判可按「本機接回音效」；本機需另有四個 WAV。中央重新連線會自動接回，並停止裁判頁的本機播放。
- 中央停止／瀏覽器暫停音訊時會嘗試主動釋放；釋放封包遺失則等心跳到期。計時與車輛授權完全不受此影響。
- 首次連線、重新連線、換場、裁判重開機都先記錄目前事件基準，不補播舊音效。過期或亂序快照也不重播。
- 裁判頁的「本頁靜音／允許無音效開始」只影響該頁，不會關閉中央喇叭。需要完全無聲，可在中央停止播放，並保持各裁判頁靜音。

## 本機資料與驗證

服務只綁定 `127.0.0.1`，不把音檔公開到區網。密碼只在本次頁面與請求記憶體中使用，不寫設定檔／localStorage／日誌；只有 IP 會記住。中央頁每次重新開啟需填密碼並按啟用。

離線測試包含真正本機 HTTP 服務、來源／路徑限制、轉送操作白名單、播放權到期／競爭、兩場重疊、事件去重／亂序／重連，以及瀏覽器音訊暫停後停止心跳。仍需以兩塊實體板及喇叭驗收延遲、音量、斷網與 Windows 休眠行為。

```powershell
.venv-check/Scripts/python -m unittest discover -s tests -v
node tests/check_central_audio.cjs
node tests/check_competition.cjs
wsl -- bash tools/check_competition_core.sh
```

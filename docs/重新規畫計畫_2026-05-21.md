## Context(為什麼做)

phone_blocky 是 ESP32(Wemos D1 R32)+ Blockly 手機 UI,跑在獨立板上,**真正使用者是「機構同事(機構設計師)」**:他們在組裝/驗證某個機構件(夾爪、手臂、輪組、雲台...)時,把該機構件接到 phone_blocky 板上,拿手機戳一戳確認動作對不對。測 OK 後該機構件**移交給程式組**接到大系統(`d--ROBOT/motorControl`,獨立 repo)正式整合。

**核心對齊問題**:目前 phone_blocky 用的命令格式(`command`+`direction:"F"`+`speed:0-255`)和 motorControl 用的(`cmd:"speed"`+ 帶正負號 RPM、`cmd:"pwm"` ±100)**語意完全不同**。機構同事報告「servo 2 在 47° 對準夾爪」時,程式組要做單位換算/方向反轉才能搬到 motorControl,跨組移交成本高。

**期望結果**:phone_blocky 的命令語意、單位、訊號方向**直接等於** motorControl 的,機構同事測出的數字可零換算搬過去。同時新增「現場拖滑桿、即時看回授、命名與儲存 preset」這些非程式員會用的功能。

**重要限制**:
- 兩個專案的 ESP32 **完全獨立**,不做硬體橋接,只做語意對齊
- phone_blocky 是測試板,**不需要** 4 輪運動學/姿態/軌跡規劃
- 馬達:**M1/M2 無編碼器**(僅 PWM)、**M3/M4 有編碼器**(可閉迴路)
- 不能打斷現在已能跑的場景 → 採加法相容、分階段推進
- 中文 UI 全部保留

## 推薦做法

### 1. 命令格式對齊:加法相容,新舊並行

- 新增 [src/CommandTranslator.h](../src/CommandTranslator.h) 前置過濾器:WebSocket 進來的 JSON 若是 `cmd` 鍵 → 轉成舊 `command` 鍵呼叫 dispatch 表;舊 `command` 鍵原路執行。舊格式繼續可用,新 UI 只發 `cmd`
- 新動詞(對齊 motorControl,**底下呼叫已存在的 `MotorController.controlMotor` / `CommandProcessor.setPIDGains` 等**):
  - `{"cmd":"pwm","motor":1,"duty":78}` — 帶正負號 PWM ±100(對應 `controlMotor` direction+speed 0-255,Translator 做轉換)
  - `{"cmd":"speed","motor":3,"rpm":80}` — 帶正負號 RPM(**僅 M3/M4**,呼叫現有 PID 設目標 ticks/sec)
  - `{"cmd":"move_to","motor":3,"deg":4700}` — centi-deg 絕對位置(**僅 M3/M4**)
  - `{"cmd":"move_by","motor":3,"deg":900}` — centi-deg 相對位置
  - `{"cmd":"stop","motor":1}` / `{"cmd":"stop"}` — 單馬達/全部
  - `{"cmd":"servo","ch":1,"deg":90}` — 對應 `servoCtrl.controlServo`
  - `{"cmd":"read","motor":3}` → 回 `{rpm_meas, deg, duty, mode}`(M1/M2 無編碼器欄位回 null)
  - `{"cmd":"capabilities"}` — 回每顆馬達是否有 encoder、PPR、減速比等,給 UI 動態渲染
  - `{"cmd":"pid","motor":3,"kp":...,"ki":...,"kd":...}` — 呼叫現有 `setPIDGains`
- PROG 模式 `{"mode":"PROG","setup":[...],"loop":[...]}` 外殼保留,只把陣列裡每個元素的動詞換新

### 2. 硬體能力 metadata

- **不再新增** `hw_config.json` LittleFS 覆蓋(現有 [include/config.h](../include/config.h) 已涵蓋大部分,且編碼器腳位是 PCNT 硬接、不適合 runtime 改)
- 改在 [include/config.h](../include/config.h) 加 metadata 陣列(編譯期常數):
  ```cpp
  struct MotorCap { uint8_t id; bool has_encoder; const char* label; };
  static const MotorCap MOTOR_CAPS[] = {
      {1, false, "M1"}, {2, false, "M2"},
      {3, true,  "M3"}, {4, true,  "M4"}
  };
  ```
- 韌體強制模式規則:`speed`/`move_to`/`move_by` 若馬達 `has_encoder=false` → 回 `{ok:false,err:"no_encoder"}`;`pwm`/`stop` 永遠可用
- `cmd:"capabilities"` 回傳這個陣列給 UI

### 3. Blockly 積木重設計

修改 [data/appBlock.js](../data/appBlock.js)、[data/app.js](../data/app.js)、[data/appIr.js](../data/appIr.js)、[data/blockly.html](../data/blockly.html) toolbox。

**保留**:digitalWrite/Read、analogWrite/Read、delay、ultrasonic、legoButton、if/while、變數、math、logic — 全部不動。

**替換馬達/舵機區塊為**:
- `motor_pwm` — 「馬達 [1-4] PWM [-100..100]」(永遠可用)
- `motor_speed` — 「馬達 [M3/M4 下拉] 轉速 [RPM]」
- `motor_position` — 「馬達 [M3/M4] 移動到 [°]」
- `motor_stop` — 「停止馬達 [1-4 / 全部]」
- `motor_read` — 「讀取馬達 [N] [rpm | 角度 | duty | 模式]」(輸出型)
- `servo_set` — 「舵機 [N] 角度 [°]」
- `servo_preset` — 「舵機 [N] 移到預設 [下拉]」(項目從 §6 抓)
- `diff_drive_lr` — 「差速車 左輪 右輪 左RPM 右RPM」(複合,**建議用 M3+M4 才有意義**)
- `estop` — 「緊急停止」

**舊 `馬達` / `舵機` block ID 保留為 deprecated shim**,載入時自動轉新 block,讓舊 Blockly XML 不會炸。

### 4. 即時觸控面板(升級現有 joy.html)

現有 [data/joy.html](../data/joy.html) 已有雙搖桿、舵機滑桿 S1/S2、M3/M4 動力/角度滑桿、連線狀態等基礎 UI,**不需要新建 quicktest.html**。

**joy.html 缺口 → 補強項目:**

1. **舵機格式升級**:現在 S1/S2 值包在 `{mode:"joy"}` 一起送,改為滑桿 `onchange` 時直接送 `{"cmd":"servo","ch":N,"deg":V}`,讓舵機立即回應、不受搖桿輪詢頻率影響。

2. **±1° / ±5° 微調鈕**:在每個舵機滑桿旁加 4 顆按鈕(−5°、−1°、+1°、+5°),每次送一次 `cmd:"servo"`,並更新滑桿顯示值。機構同事夾爪要 47° 還是 48° 靠手感,這個非常重要。

3. **緊急停止**:頂部加大紅色按鈕,送 `{"cmd":"stop"}` 停全部馬達。

4. **馬達 PWM 直控**:M1/M2 的滑桿由舊的 `-254~254` 範圍改為 `±100`,送 `{"cmd":"pwm","motor":N,"duty":V}`;M3/M4 動力模式同樣改。(角度模式等 Phase C encoder 就緒後再接。)

保留不動:雙搖桿差速車控制(`mode:"joy"`)、按鈕 1/2、連線狀態 LED — 這些已可用。

### 5. 遙測(輕量化)

現有 `getSysIdResultsJson` 是用拉的(SysId 結束後一次性回);**新增即時推送 task** 給即時測試面板用。

新增 [src/TelemetryStreamer.h](../src/TelemetryStreamer.h):FreeRTOS task,訂閱者存在時每 100 ms 廣播,**格式對齊 motorControl 的 `read` response**:

```json
{"type":"telemetry","t":12345,
 "motors":[{"i":3,"mode":"speed","rpm_meas":78.4,"rpm_cmd":80,"deg":12340,"duty":62}],
 "servos":[{"i":1,"deg":47}]}
```

M1/M2 的 rpm_meas/deg 設 null,UI 顯示「—」。`cmd:"subscribe"` 讓 UI 進/出即時測試分頁時切換訂閱,省頻寬避免 jitter(對應最近修 jitter 的 commit)。

### 6. **命名與 Preset 匯出**(跨組移交的核心產出)

這是**最關鍵的產出物**,真正解決跨組移交斷層的點。

新增 [src/PresetsStore.h](../src/PresetsStore.h) + [data/presets.html](../data/presets.html) + `presets.js` + LittleFS [data/presets_store.json](../data/presets_store.json)。

機構同事可以:
- 為每個通道命名:「馬達 3 = arm_J2」、「舵機 2 = gripper」
- 標註減速比、極限角度
- 為任何通道儲存帶名稱的數值:「gripper_open=47°」、「gripper_close=138°」、「home=0°」
- 對 M3/M4 也可存「跑 SysId 後的特性曲線」與「調好的 PID 三參數」

匯出 schema(版本化):

```json
{
  "schema": "phone_blocky.handoff/v1",
  "device_id": "bench-03",
  "saved_at": "2026-05-21T10:14:00+08:00",
  "channels": {
    "motor": {
      "3": {"label":"arm_J2","has_encoder":true,
            "gear_ratio":48,"ppr":360,"encoder_pos":"after_reducer",
            "pid":{"kp":2.0,"ki":0,"kd":0.1},
            "presets":{"home":{"deg":0},"stow":{"deg":-9000}}}
    },
    "servo": {
      "1": {"label":"gripper","min_deg":20,"max_deg":160,
            "presets":{"gripper_open":47,"gripper_close":138}}
    }
  }
}
```

**所有數值都用 motorControl 的原生單位**(帶正負號 RPM、centi-deg、°、PWM ±100)— 這就是「直接拷貝、不用換算」的承諾。

HTTP 端點:
- `GET /api/presets/export` — 手機下載 JSON
- `GET /api/capabilities` — 即時測試面板開啟時讀

## 驗證(每個 phase 結束的測試)

**Phase A**:
1. 編譯通過、燒入後 ESP32 啟動正常、AP SSID 出現
2. 手機開 Blockly,舊 `馬達` block 設 M1 + FORWARD + 200 → M1 正轉
3. 拉新 `motor_pwm` 設 M1 PWM=+78 → M1 正轉,扭力與舊版一致
4. 對 M1 下 `cmd:"speed", rpm:60` → 回 `{ok:false,err:"no_encoder"}`;對 M3 下同樣命令 → 接受
5. WebSocket console 看 emit 的 JSON:舊 block 仍 `{"command":"motor_control"...}`、新 block `{"cmd":"pwm"...}`,兩者都到達 MotorController

**Phase B**:手機開 joy.html → 拖舵機滑桿 → 馬達/舵機即時回應;按 ±1°/±5° → 角度微調;按緊急停止 → 所有 motor/servo 停;M1-M4 PWM 滑桿驅動正確。

**Phase C**:M3 下 `cmd:"speed", rpm:60` → 儀器量 57-63 RPM;`cmd:"move_to", deg:9000` → 停 88-92°;即時測試分頁的 RPM 數字持續更新無卡頓。

**Phase D**:在預設管理頁標 servo 2="gripper",存 `gripper_open=47, gripper_close=138`,匯出 JSON → 程式組在 motorControl 端讀取後 `cmd:"servo","ch":<對應馬達>,"deg":47` → 夾爪角度與機構同事測的一致(實機驗證)。

每個 phase 都要在**實機機構件上跑一遍**,不能只靠 unit test — 這就是「測機構」的工具。

# ESP32 Phone Blocky 更新紀錄

## 2026年10月13日 更新

### ⚙️ 直譯器：頂層 loop 整圈執行、程式執行中照常處理 I2C 主機命令

**需重新燒錄韌體**（`pio run --target upload`；I2C 從機板用 `-e esp32dev_i2c`）。

- **頂層 loop 每 10 ms 整圈跑完**（原本每拍只跑一條）。舊行為下 loop 有 N 個積木就額外多出
  N×10 ms，同一段積木放不放進「重複」時序不同；現在兩者一致。指令之間仍維持約 10 ms 的
  角度控制節拍。**注意**：loop 裡沒有任何延遲的程式，現在每 10 ms 就整圈重跑一次，
  動作會比以前密；需要節奏請放「延遲」。
- **I2C 從機：delay／迴圈期間也落地主機命令**。原本主機的 STOP_ALL、0x65 設定值要等程式
  回到主迴圈才處理——「前進 5 秒」期間按停止要等 5 秒；「等到主機設值才開始」的 while 會永遠等不到；
  佇列（16 筆）還可能溢位丟命令。現在 `programYield()` 與指令之間約每 10 ms 呼叫
  `setProgramServiceHook` 注入的 `i2cBridge.service()` ＋ `checkLink()`。
  （STOP_ALL 仍只停致動器，不會終止積木程式；程式下一個動作指令會再讓馬達動。）


### 📚 內建範例改成產生式：DSL → XML，28 支分六個系列

**需 `uploadfs`。** 範例不再手改 XML。原始檔放在 `tools/examples_src/<id>.cjs`，用
`tools/examples_src/_dsl.cjs` 寫，再由 `node tools/gen_examples.cjs` 產生 `data/examples/*.xml`
與 `index.json`。

- **28 支範例、六個系列**：A 動起來、B 角度、C 感測與腳位、D 邏輯資料、E 整合、F 對外 I2C。
  📚 抽屜依系列分組，找範例時不用一支一支翻。
- **`index.json` 每支多一個 `blocks` 清單**，記錄該範例用到哪些積木。
- **`gen_examples.cjs --check` 擋手改**：`data/examples/` 與原始檔產生的結果不一致就失敗，
  `check_examples.cjs` 開頭也會跑這一步。
- **積木覆蓋率強制檢查**（`REQUIRE_FULL_COVERAGE`）：現在 45 種積木都有範例用到。以後新增積木，
  要嘛補一支範例，要嘛在 `EXEMPT` 寫明理由，否則測試不過。
- **`03-ultrasonic-stop` 改名為 `11-ultrasonic-stop`**，編號歸入 C 感測與腳位系列。
  若有人記得舊 id，請改用新的。
- **範例總量上限提高到 128 KB**，28 支範例放得下。

翻寫方式與 id 編號規則見 [範例程式.md](範例程式.md)。

### 🔍 撰寫範例時發現的韌體行為

寫範例時讀韌體原始碼（`CommandProcessor.h`）確認的行為，**尚未上板實測**，之後寫程式或改韌體時要注意：

- **`digitalRead` 會強制把腳位設成 INPUT**，所以前面的 `pinMode` 沒有作用。
- **LEGO 按鈕（`lego_button`）在 INPUT_PULLUP 下回傳原始電位**，程式要自己判讀高低電位的意思。
- **`move_by` 以「目前實際位置」為基準**加上位移量，不是以上一次的目標角度；上一段還沒走完就下一道，
  會比預期少走，所以分度範例每步之間要等馬達到位。
- **重複下 `move_to` 會打斷保持**：每一道都會回到驅動階段並清掉積分，所以 `move_to` 要放 setup，不要放 loop 一直送。
- **`plot_print` 所有系列共用一個 50 ms 冷卻**：同一支程式畫兩條線時，兩條會共用這段冷卻，
  不會各自有 50 ms。

## 2026年10月11日 更新

### 🧩 積木「感測器」分類補齊，新增編碼器讀值

**需重新燒錄韌體並 `uploadfs`。** 工具箱的「感測器」原本只有超音波與 LEGO 按鈕兩個，
現在是板子上所有讀得進來的東西：

- **新增具名的「紅外線感測器(數位)」「紅外線感測器(類比)」積木**（預設 GPIO15 / GPIO32）。
  通用的「數位讀取腳位 15」名字裡看不出在量什麼，放進感測器分類也還是像 Arduino 的東西；
  板子上接的就是紅外線模組（硬體檢測頁那兩項測的也是它）。這兩顆產生的 JSON 與
  `digitalRead` / `analogRead` **完全相同**，共用同一個翻譯器，韌體不必認識新指令。
- **數位讀取 / 類比讀取在「感測器」分類也放一份**（在最後，給沒具名到的其他模組用）。
  要找感測器的人不會想到去 Arduino 分類翻；但它們在 Arduino 分類裡仍然保留，因為在那邊
  是與 digitalWrite / analogWrite 成對的 GPIO 基本積木。Blockly 允許同一種積木出現在多個
  分類，拖出來是同一顆。
- **新增 `encoder_read` 積木**：讀 M3/M4 編碼器的**角度 (°)／計數 (ticks)／轉速 (RPM)**。
  這是真正缺的東西 —— 在此之前學生可以用 `move_to` 把馬達轉到某個角度，卻沒有任何積木
  能「讀回」目前角度：撞到東西停住、或被外力推走，程式完全看不出來。
  韌體新增 `{"command":"encoderRead","motor":3,"read":"deg"}` 表達式（`readSensorValue()`），
  角度相對「設目前位置為 0°」的零點，只有 M3/M4 有效（其他馬達回 0，積木下拉也只給 3/4）。

清點結果：板子上沒有其他已接但讀不到的感測器（沒有 IMU，電池電壓分壓是 `i2cESP32`
那塊板的電路）。

### 🔧 硬體檢測：補上三項漏掉的硬體 + 轉向判定

**需重新燒錄韌體並 `uploadfs`。** 清點 `include/config.h`、`docs/腳位.md`、
`hw_config.json` 與韌體 `handleHardwareTest()` 之後，補上原本九項沒涵蓋的硬體：

- 💡 **數位／PWM 輸出**（預設 GPIO 2 / GPIO 26，腳位可改）：原本九項**全是輸入或馬達**，
  輸出方向一條驗證路徑都沒有 —— 而 Blockly 的「數位寫入」「類比寫入」積木（學生接 LED、
  蜂鳴器）走的就是這條路徑。韌體新增 `test:"outputTest"`，並用白名單
  `isUserOutputPin()` 擋掉板子自己佔用的腳位（595、馬達 PWM、舵機、編碼器）——
  檢測頁誤填一個腳位就讓馬達失控是最糟的失敗模式。
- 🔄 **編碼器手轉**：不驅動馬達，用手轉 M3/M4 看計數變化。原本編碼器只在馬達被驅動時
  順便驗到，馬達不轉時分不清是馬達／驅動板壞還是編碼器沒接好。
- 🔌 **I2C 從機連線**（GPIO21/22, 0x36）：橋接層統計原本**只印在序列埠**，現場用手機
  完全看不到。韌體新增 `test:"i2cStatus"`，由 `main.cpp` 注入統計提供者
  （CommandProcessor 不能 include I2CSlaveBridge，會循環相依）。桌上模式韌體回
  `supported:false`，網頁明講「這支韌體沒有這個功能」，而不是假裝沒連上。
- 🧭 **M3/M4 轉向自動判定**：正轉段計數應增加、反轉段應減少。只看 min/max 的話，
  編碼器 A/B 接反或馬達兩條線接反都看不出來（計數照樣在變，但方向是錯的）。
  現在會直接講「方向一致 / 方向相反（接線接反）/ 兩段同方向（只讀到一相）」。
- 📶 **WiFi 實況**：面板顯示 SSID、RSSI 與品質評語。WebSocket 通不通只說明「現在這條
  連線」，訊號掉到 -80 dBm 以下時檢測會斷斷續續，看不到訊號強度就查不出來。

檢測項目表（`TEST_ITEMS`）現在是單一真相，報告的項目清單也改成從它推導，不再另外維護
兩份 mapping。測試 `tests/check_hardware_test.cjs` 同步擴充到 12 項，並新增輸出序列、
手轉變化量、I2C 兩種韌體回應、轉向判定（正常／兩段同方向）的案例。

> 不適用的硬體：電池電壓量測是 `i2cESP32` 的 GPIO35 分壓電路，在這塊板上 GPIO35 是
> M3 編碼器 A 相。

### 🔧 硬體檢測頁：執行流程修好了，版面改成手機可用

**需 `uploadfs`。** 這一頁的「開始全部檢測 / 開始勾選檢測」原本按下去**什麼都不會發生**，
不是視覺問題而是真的壞掉：

- `updateProgress()` 去抓 `progress-m1` / `progress-m2` / `progress-button` /
  `progress-complete` 四個元素，那是更早版面留下的、現在的 HTML 裡根本沒有，
  於是它在 `element.classList` 丟 TypeError。它被兩個 reset 函式呼叫，而 reset 又排在
  `executeNextAutoTest()` 前面 —— 整個函式就在那裡中斷，一個測試都不會開始。已移除，
  進度一律走 `updateProgressBar()`。
- `window.onload` 會把九段詳細測試區全部設成 `pointer-events:none`。不只是變灰，是連
  每一段自己的「開始測試」按鈕、以及測完跳出來的「✅ 是／❌ 否」確認鈕都按不下去。
  改成「收合」而不是「鎖住」。
- 「開始全部檢測」走的 `resetAllTestSections()` 只處理六段、而且全部關掉卻從不打開。
  兩個 reset 合併成一個，涵蓋九段。
- 感測器測試按「停止監測」只會清掉讀取迴圈，不會跳確認框，也不取消那個「N 秒後自動停」
  的 timeout —— 看起來像當掉，而且殘留的 timeout 會在下一個測試跑到一半時冒出來。
  現在按停止立刻跳確認框，並取消待辦的 timeout。
- 「🔄 重置」沒有還原 M1/M2 與三個感測器的開始按鈕、沒有隱藏它們的確認框、沒有停掉還在跑的
  讀取迴圈。現在是完整重置。
- 執行訊息原本用 `appendLog('connectionStatus', …)` 塞進「🔴 WebSocket 未連接」那顆狀態
  藥丸裡，把它撐成一團逐行累積的文字。改到面板下方獨立的「執行紀錄」。
- 未連線時 `sendCommand()` 會跳 alert —— 感測器測試每 200–500ms 送一次，等於連環 alert
  關不掉。改成開始前先檢查連線擋下來；執行中斷線則自動中止並停掉馬達。
- 馬達測試序列是遞迴 `setTimeout` 鏈，中止時收不掉。改用 runToken：中止／重置會讓還在跑的
  序列下一步自己停下來。

版面：

- 九段詳細測試區**預設收合**，正在跑的那一段自動展開並捲到畫面上（原本手機要自己往下找）。
- 新增**底部固定執行列**：顯示「[3/9] 正在測試…」並永遠有一顆「■ 中止檢測」。
  硬體檢測會讓馬達真的轉起來，「怎麼停」必須隨時在手邊。
- 進度改成依「第幾項／共幾項」計算（原本每個測試各自寫死 25/50/60/70/75/80%，
  只勾兩三項時第一項就顯示 75%）。
- 檢測項目卡改成 `<label>`，**整張卡都可以點**（原本只有 20px 的小方框可點，手機上很難中）。
- 配色統一成其他頁的 #4d7fff / #2f9e6b / #ee5a52（原本綠框面板 + 紫色確認框 + 黃色提示框
  三種風格混搭），間距改用 `clamp()`，手機不再被 40px 的留白吃掉寬度。
- 修掉頁面裡四處編碼破損的字元（`�`）。

新增 `node tests/check_hardware_test.cjs`：用假 DOM + 假時鐘把整頁跑起來，驗證
啟動 → 執行 → 確認 → 下一項 → 出報告整條鏈、中止會停馬達並清計時器、提早停止會跳確認框、
未連線不得啟動、重置會還原。拿這支測試去跑改動前的頁面會立刻失敗。

### 📚 積木頁內建範例程式

**需 `uploadfs`。** 積木頁頂列加了 **📚**，點一下開範例面板，再點一下就把一支現成程式
載入到畫布。以前打開積木頁只有空的 setup／loop，不知道一支能跑的程式長什麼樣，
就只能等人傳 `.xml` 過來。

- 範例放**頂列**而不是 ☰ 抽屜裡：第一次用的人正是最需要範例、也最不會去翻選單的人。
  頂列多一顆按鈕後 390px 螢幕擺不下完整標題，窄螢幕會把標題文字收掉只留 🧩。
- 範例面板與 ☰ 抽屜是兩個獨立面板、共用同一塊遮罩，一次只開一個。

- 目前三支：**轉一下、停一下**（M1，`pwm`/`delay`/`stop` 的最小程式）、
  **舵機轉到 90°**（S1，`servo` 角度指令）、
  **超音波避障**（M1＋超音波，`if/else` + `plot_print`）。
- 範例放在 LittleFS 的 `data/examples/`（清單 `index.json` + 每支一個 `.xml`），
  **不碰板子上的存檔**。板子上只存一支程式（開機自動執行跑的就是那支），範例若去
  佔用它，載入範例就等於把人家寫好的程式蓋掉。
- 載入後標成「未存檔」：範例只存在網頁上，不標的話會讓人以為板子上已經有這支。
  要執行或開機自動跑，還是得按「存到 ESP32」。
- 積木上附了說明氣泡（💬），寫的是「哪個數字可以改、改了會怎樣」。
- 清單是抽屜第一次打開才抓，開頁不多花一個來回；抓不到時直接告訴你解法
  （`pio run --target uploadfs`），那才是最常見的原因。

  （`appIr.js`/`appJson.js`/`app.js`）離線驗證每支範例 —— 積木／欄位／插槽名稱、
  下拉選單合法值、有沒有空的數值插槽、整支能不能變成合法 PROG JSON（含 8 層上限）、
  `index.json` 與檔案是否一一對應。範例是手寫 XML，沒有這道關卡只能一支一支上板子試，
  而壞掉的範例比沒有範例更傷。

### 📱 積木頁改成手機用的固定版面（app shell）

**需 `uploadfs`。** 整頁不再上下捲動，固定分成四條：頂列（看全部／整理／☰ 選單）、
積木工作區、訊息列、底列（停止／執行）。

- 舊版是長頁面、積木區只是中間一個固定高度的視窗，結果頁面和積木畫布**兩層都會捲**，
  手指在畫布邊緣一拖，瀏覽器分不出要平移畫布還是捲頁面；而且一捲頁面，正在編輯的
  工作區就有一半移出螢幕。現在唯一會動的只有畫布。
- 新增 **⤢ 看全部**：一下把整支程式縮到剛好塞滿畫面（`zoomToFit`），直接解決
  手機上「看不到全部」。另有 **⇅ 整理積木**：排成一直欄後自動看全部。
- **兩指縮放本來就能用**，只是沒人知道（Blockly 的 `pinch` 預設跟著 `wheel`／`controls` 開）。
  另外加上 `maxScale 2.0` / `minScale 0.3` 護欄，否則「看全部」在程式只有兩三個積木時
  會放大到離譜、程式很長時又縮到看不見字。
- **執行／停止移到底列**（手機上拇指最好按的位置，而且編輯時永遠看得到）。
- **系統訊息收成底部一行**，只顯示最新一條，點一下展開完整面板。錯誤訊息要在編輯時
  就看得到才有用，所以它固定在畫面內、不會被捲走。
- 存檔／開啟／開機自動執行／Plotter／回首頁收進 **☰** 選單（底部面板）。這些是偶發操作，
  不該在編輯時佔掉垂直空間；檔案操作按完選單會自動收起，免得結果訊息被蓋住。
- 桌機維持原本「藍底 + 白卡」外觀，只是改成滿高不捲動。

> 手機上寫大程式仍然會擠，那是 390px 寬螢幕的物理限制。建議手機當現場操作與微調的
> 介面，大程式在平板或電腦上寫完「下載到本機」存成 `.xml` 再帶過來。

### 📶 WiFi 設定：存不進去不再偽裝成存好了

**需重新燒錄韌體並 `uploadfs`。**

- `/setwifi` 的每個 NVS 寫入都會驗證，失敗回報失敗並**明講哪一步失敗、而且不重開機**。
  舊版寫入失敗也回「已儲存」然後重開，等於把「設定沒存進去」偽裝成「存好了但連不上」，
  這兩種情況在畫面上完全無法分辨。
- 新增 `GET /api/wifi`：已存 SSID、密碼長度（不回密碼）、連線狀態與**中文原因**、
  IP／訊號／channel、下次重試倒數、AP 名稱與連線數。`set.html` 頁首會顯示並每 5 秒更新。
  最關鍵的是狀態碼：**1 = 掃不到這個 SSID**（名稱打錯，或那是 5GHz——ESP32 只有 2.4GHz）、
  **4 = 掃到了但關聯失敗**（幾乎都是密碼錯）。
- **STA 背景自動重連**，退避 5→10→20→40→60 秒。舊版開機只試一次 10 秒，失敗就永遠
  停在 AP-only，路由器比板子晚開機就中獎。
- AP + STA 都有時，**AP 名稱改成精簡格式**：`243C-192.168.0.12`（原本
  `ESP32-243C (192.168.0.12)` 在手機 WiFi 清單裡會被截掉尾巴，而被截掉的正好是 IP）。
  自訂的控制板名稱不會被換成 MAC，只改用同樣精簡的分隔。另外守住 SSID 的 32 bytes
  上限並在 UTF-8 字元邊界截斷——超過會讓 `softAP()` 直接失敗、AP 整個不見。
- 修正「只存 WiFi」會把控制板名稱清空：名稱欄位是 `display:none` 而不是 `disabled`，
  瀏覽器照樣會送出 `name=""`，而舊版無條件寫入。
- 設定頁的重開機改成延遲執行，不再在 AsyncWebServer 的 callback 裡 `delay` + 重開
  （那會卡住 AsyncTCP、回應常常還沒送完就被切斷）。

### 🔧 從機韌體的 JSON 巢狀上限掉回 10（已修）

`platformio.ini` 的 `[env:esp32dev_i2c]` 覆寫了 `[env]` 的 `build_flags`，
`-DARDUINOJSON_DEFAULT_NESTING_LIMIT=32` 在從機韌體裡整個消失，巢狀上限掉回
ArduinoJson 預設的 10（只夠 3 層積木）。症狀是**同一支程式在桌上模式跑得好、
燒成從機版就解析失敗**。已補上 `${env.build_flags}`。

## 2026年10月9日 更新

### 🔁 Blockly 支援迴圈與多層巢狀

- 「流程控制」新增 **重複 N 次**、**當條件成立時重複／重複直到條件成立** 兩種積木。
- 如果／重複／當…重複 可互相包，**最多 8 層**（原本「如果」實際只能包 3 層，第 4 層會整支程式解析失敗）。
- 超過 8 層時網頁直接提示「積木巢狀太深」，不送出；韌體也會回 `nesting_too_deep`，不再是看不懂的 `json_parse_failed`。
- 迴圈裡的指令連續執行，需要間隔請自己加延遲；按「停止」可隨時中止，含永不結束的迴圈。迴圈中 M3/M4 角度保持照常運作。
- 韌體：`platformio.ini` 放寬 ArduinoJson 解析深度（10 → 32）；`jsonTask` 堆疊 8 KB → 12 KB。**需重新燒錄韌體並 uploadfs。**
- AI 自然語言產生程式暫不使用迴圈。

### 🔢 數值插槽、且／或、不再默默略過積木

- 馬達動力、轉速、移動／旋轉角度、舵機角度、延遲毫秒改成**可接積木的插槽**：放數字和以前一樣，也可以放變數、感測器或算式，例如「舵機角度 = i × 10」。超出範圍時韌體自動夾限（動力 ±100、舵機 0–180）。
- **舊存檔不用重做**：開啟舊程式時，原本填的數字會自動變成插槽裡的數字積木，產生的指令和以前完全相同。
- 「邏輯」新增 **且／或** 積木，可寫「超音波 < 20 且 按鈕按下」。
- 沒接在 setup／loop 裡的積木，執行或存檔時會提示「有 N 個積木不會執行」；不支援的積木會直接報錯，不再默默略過。
- 刪除舊版「馬達」「舵機」積木（功能與馬達模組的新積木重複）。含這兩個積木的舊存檔將無法開啟。

### 📁 存檔分成 ESP32 與本機

- 「程式操作」改成兩組四個按鈕：**存到 ESP32／從 ESP32 開啟**、**下載到本機／從本機開啟**。
- 新增「從本機開啟」：以前下載的備份檔打不回來，現在電腦和手機都能選 .xml 檔載入。
- 下載可自訂檔名；修正 iPhone Safari／Firefox 可能下載失敗的問題。
- 畫面有未存修改時開啟前會確認；要覆蓋 ESP32 上別的程式時會先提醒。開啟失敗時畫面上的積木保持不變。

### 💾 修正存檔

- **問題**：約 30 個積木以上的程式「存檔後讀回驗證失敗」或無法開啟；再大一點直接 `bad json: NoMemory`。
  原因是韌體讀回時把 XML 塞進固定 8 KB 的緩衝（XML 被默默丟掉），存檔解析也只多留 1 KB；
  而且預設 NVS 只有 20 KB，單筆上限約 8 KB。
- **修正**：
  - 存檔／讀回改成不經固定大小緩衝，資料原樣存、原樣讀回（前端讀回後逐字比對 XML）。
  - 新增 128 KB 的程式專用儲存區（flash 末端未使用的空間），舊存檔與「開機自動執行」設定第一次開機時自動搬過去；WiFi、PID 設定與網頁檔都不受影響。
  - XML 不再存積木 ID，約小 20%。
  - 上限改為 32 KB（約 140 個動作積木）；超過時存檔前就會提示，錯誤訊息改成中文。
- **需要重新燒錄韌體**（`pio run --target upload` 會一併寫入新的分割表），網頁也要 `uploadfs`。

### 🧩 副程式

- 新增「副程式」分類：把一段積木包成副程式（可加參數，例如「夾爪（角度）」），再用呼叫積木重複使用。
- 副程式可以呼叫其他副程式，但不能直接或間接呼叫自己；呼叫算一層，和如果／迴圈合計最多 8 層。
- 暫不支援有回傳值的副程式。
- 被停用（右鍵「停用積木」）的積木不會執行。

### 🧮 數學積木加強

- 運算積木新增 **餘數**，符號改成 + − × ÷。
- 新增 **絕對值**、**隨機整數 從…到…**、**限制…在…到…之間**、**對應換算**（原範圍 → 新範圍，例如距離 0–100 cm → 舵機 0–180°）。
- 運算、比較積木的插槽沒放東西時會直接提示，不再默默當成 0。
- 仍是整數運算（÷ 捨去小數）。

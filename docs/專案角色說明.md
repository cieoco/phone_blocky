# phone_blocky 專案角色說明

> 2026-05-21 釐清。本文件用於對齊團隊對 phone_blocky 的定位認知,避免後續實作走偏。

## phone_blocky 是什麼

phone_blocky 是**機構組同事在現場驗證機構件的桌上測試板**,跑在獨立的 ESP32(Wemos D1 R32)上,透過 WiFi AP + Blockly 手機網頁讓非程式員也能戳。

**典型使用場景**:
1. 機構同事剛做好一個機構件(夾爪、手臂關節、輪組、雲台...)
2. 他/她把該機構件直接接到 phone_blocky 板上
3. 拿手機連 phone_blocky 的 WiFi AP、開網頁
4. 拖滑桿/按按鈕戳一戳,確認機構動作對不對、角度對不對、方向對不對
5. 測 OK 後,移交給程式組整合進 `d--ROBOT/motorControl`(大系統)

## 與 motorControl 的關係

phone_blocky 與 `d--ROBOT/motorControl` 是**兩塊獨立的 ESP32 板**:

| | phone_blocky | motorControl |
|---|---|---|
| 角色 | 機構驗證測試板 | 機器人主控系統 |
| 使用者 | 機構組(不擅程式) | 程式組 |
| 階段 | 機構件組裝/測試 | 整合後正式運行 |
| UI | 手機網頁 + Blockly + 滑桿 | Python GUI / Serial / WebSocket |
| 控制方式 | 簡單(PWM、即時拖) | 閉迴路(PID、姿態、軌跡) |

**它們之間沒有硬體橋接**,在工作流程的不同階段被不同人使用。

## 為什麼要對齊

phone_blocky 目前的命令格式(`motor_control` + `direction:"F"` + `speed:0-255`)與 motorControl(`cmd:"speed"` + 帶正負號 RPM、PWM ±100、`cmd:"servo"` + 角度)語意完全不同。

機構同事測完報告「servo 2 在 47° 對準夾爪」時,程式組要做單位/方向/編碼換算才能把 47 寫進 motorControl。這個翻譯步驟容易出錯,而且重複發生。

**對齊後的承諾**:phone_blocky 量出來的所有數字(角度、RPM、PWM 比例),程式組可以**零換算**直接搬到 motorControl。

## 重新規畫的範圍與限制

- **要做的**:命令語法/單位對齊、即時觸控滑桿面板、編碼器讀回、Preset 命名與匯出
- **不做的**:4 輪運動學、姿態追蹤、軌跡規劃 — 這些是 motorControl 的職責
- **馬達數**:實際 4 顆,部分有編碼器、部分沒有 — firmware 需分流
- **既有問題**:motor5 用 GPIO {13, 5},與兩顆 servo({5, 13})打架 → 直接移除 motor5/6 解決
- **中文 UI 全部保留**

## 重新規畫計畫

詳細的階段化計畫見 [重新規畫計畫_2026-05-21.md](重新規畫計畫_2026-05-21.md)。5 個階段:

1. **Phase A** — 協定/單位對齊(加法相容,不破壞既有)
2. **Phase B** — 即時觸控面板(機構同事的主力 UI)
3. **Phase C** — 編碼器 + 閉迴路控制
4. **Phase D** — **Preset 命名與匯出**(跨組移交的核心產出物)
5. **Phase E** — 退役舊格式(選用)

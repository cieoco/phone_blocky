# ESP-NOW 相撲比賽：建置與操作

裁判網頁已加入同頻道 ESP-NOW 搜尋、隊伍登記／配對，以及學生原網頁同意後更換裁判的流程；比賽計時與授權管制沿用既有實作。尚未完成兩塊以上實體板的無線與機構驗收。學生競賽板使用原 ESP32；裁判可用一般 ESP32 或 ESP32-S3-Zero（4 MB Flash），必須選擇對應建置環境，兩者韌體不可互燒。

## 連線速查

以下適用於已分別燒錄對應韌體及網頁的板子；首次燒錄見第 1 節。

| 使用者／方式 | 手機或電腦連哪個網路 | 瀏覽器開啟 | 看到的頁面 |
|---|---|---|---|
| 裁判經路由器連線 | 與裁判板相通的現場路由器網路 | `http://<STA IP>/`，IP 從裁判 AP 名稱讀取 | 登入入口 → A 場／B 場裁判 |
| 裁判直接連板子 | 裁判 AP，例如 `A1B2-192.168.1.50` | `http://192.168.4.1/` | 同一登入入口與分流頁 |
| 喇叭 PC | 同一現場網路或裁判 AP | 同一裁判板網址 | 登入入口 → 中央音效台，不需 Python |
| 學生操控自己的車 | 自己學生板的原 AP，例如 `ESP32-XXXX` 或自訂名稱 | `http://192.168.4.1/` | 原首頁、Blockly、搖桿與設定頁 |

裁判 AP 名稱沒有 `Ref-` 前綴：前段 `A1B2` 是 MAC 末四碼，後段是目前 STA IP；以上名稱與 IP 均為範例。只需查看 Wi-Fi 清單即可讀取 IP，不必先連裁判 AP。若顯示 `A1B2-STA-offline`，代表裁判尚未連上路由器；仍可直接連 AP 開管理頁，但**目前版本不能在 STA 離線時準備比賽**。

`192.168.4.1` 指的是目前連接的那塊板子；連學生 AP 就是學生頁，連裁判 AP 才是裁判頁。學生手機繼續連自己的車，裁判板透過 ESP-NOW 傳送比賽狀態與授權。

密碼依用途分開：現場路由器使用路由器密碼；裁判 AP 與裁判網頁共用板上產生的裁判操作密碼；學生 AP 使用原密碼。首次取得裁判密碼時，將裁判板接 USB、關閉序列監視器，再執行下列查詢（COM5 換成實際埠，需要 `pyserial`）：

```powershell
python tools/competition_pair.py --info COM5 --show-credentials
```

回傳的 `key` 是裁判 AP／網頁操作密碼，`ip` 是 STA IP，`ap_ip` 是 AP IP；請勿公開這段輸出。這是首次取得登入資訊的方式，日常車輛登記與更換裁判不需接 USB：進裁判頁按「搜尋附近車輛」，操作見第 2 節。

要自訂裁判密碼，兩場先清場回待賽、結束配對，再從 USB（115200 baud）送出一行 JSON：`{"cmd":"competition_set_password","password":"<自訂密碼>"}`。將佔位文字換成 8–32 個可列印 ASCII 字元；指令僅裁判 USB 接受，成功回覆後會自動重開機。AP Wi-Fi 與網頁共用此密碼，舊登入頁需回首頁重新登入。密碼只儲存板上 NVS，不影響路由器帳密、隊伍或配對金鑰；不要把含真實密碼的指令保存至版本庫。

## 1. 準備控制板

新增一塊裁判 ESP32 管理 A／B 兩場；學生車沿用原本的 phone_blocky 控制板，不需加裝另一塊學生板。一場可選 1–4 台車（單台供測試），兩場合計上限 4 台，名冊最多 64 隊。裁判以 STA 連接現場 2.4GHz 路由器，學生車必須使用相同頻道（目前接受 1–11）。

裁判的路由器帳密由本機 `include/referee_wifi.local.h` 提供，格式見 `include/referee_wifi.example.h`；前者已被 Git 排除。只在本機填入，不能放進公開範例、build_flags 或網頁資料夾。編譯產生的韌體會包含這份本機設定，建置產物也不得加入版本庫。沒有本機設定檔仍可編譯並由 AP 進管理頁，但 STA 未連線時不能準備比賽。

裁判 **AP＋STA 同時開啟**。AP 名稱例如 `A1B2-192.168.1.50`（範例 IP），讓手機在 Wi-Fi 清單直接看到 STA IP；名稱前段為 MAC 末四碼，用來區分板子。STA 未連線時顯示 `A1B2-STA-offline`。連接裁判 AP 可開 `http://192.168.4.1/`，連路由器則開名稱中的 STA IP，兩者是同一裁判網頁。AP 密碼沿用板上產生的裁判操作密碼，與路由器密碼分開。

STA 連線／失聯或 DHCP IP 改變時會更新 AP 名稱；IP 沒變就不反覆重設 AP。名稱改變時手機可能需要重新選取新的 AP 名稱。

| 韌體角色 | 行為 | 網頁資料來源 |
|---|---|---|
| `esp32dev_referee` | AP＋STA 裁判計時、名單、ESP-NOW 授權，不初始化致動器 | `referee_data/` |
| `esp32s3_zero_referee` | ESP32-S3-Zero／4 MB Flash 裁判，同樣功能；原生 USB Serial/JTAG | `referee_data/` |
| `esp32dev_competitor` | 原學生韌體加裁判管制；未參賽可正常操作，參賽期間才需授權 | 原有 `data/`，增加共用狀態列 |
| 原有 `esp32dev`／`esp32dev_i2c` | 保持既有教學／I2C 模式，不能當成已受裁判限制的競賽車 | 原有 `data/` |

先只編譯與打包，不連板也可執行：

```powershell
pio run -e esp32dev_referee -e esp32dev_competitor
pio run -e esp32dev_referee -e esp32dev_competitor --target buildfs
```

確認板子、序列埠及馬達供電狀態後，分別燒錄。以下 COM5／COM6 是範例，需換成實際值：

```powershell
pio run -e esp32dev_referee --target upload --upload-port COM5
pio run -e esp32dev_referee --target uploadfs --upload-port COM5
pio run -e esp32dev_competitor --target upload --upload-port COM6
pio run -e esp32dev_competitor --target uploadfs --upload-port COM6
```

兩種角色的 `uploadfs` 不可互換。裁判的建置腳本會自動使用 `referee_data/`；repo 不附 WAV，未提供本機音檔也能建置。音效準備見第 5 節；學生板保留原首頁、Blockly、搖桿與設定頁。這次未更動分割表。**雙場版本須更新裁判韌體與裁判 uploadfs；已使用最新 ESP-NOW v2 competitor 的學生板不用因此重燒。** 若學生仍是早期 v1 或一般教學韌體，則需一起更新為 v2 competitor 與其網頁。手機重新載入頁面。

### ESP32-S3-Zero 裁判板

4 MB Flash 型號使用 `esp32s3_zero_referee`，沿用本專案分割表與 LittleFS；裁判功能使用內部 RAM，不啟用 PSRAM。此環境使用 S3 通用板型定義並覆寫為 4 MB，啟用原生 USB CDC；不能使用上面的 `esp32dev_referee` 韌體。學生環境保持原設定。

用可傳資料 USB-C 線連接，首次燒錄可按住 BOOT 再插入 USB，放開 BOOT。已插線時也可按住 BOOT、按一下 RESET 後放開 BOOT。關閉序列監視器，執行以下指令；COM4 是範例，實際以 `python -m serial.tools.list_ports -v` 查到的 USB 埠為準。

```powershell
pio run -e esp32s3_zero_referee
pio run -e esp32s3_zero_referee --target upload --upload-port COM4
pio run -e esp32s3_zero_referee --target uploadfs --upload-port COM4
python tools/competition_pair.py --info COM4
```

燒錄後若仍停在下載模式，放開 BOOT 並按一次 RESET。重新列出序列埠；原生 USB 埠可能重新枚舉。查詢時加 `--show-credentials` 可在本機取得裁判 AP／登入密碼，請勿存進版本庫。確認 STA 已連線後，開啟回傳的 IP 即可登入；日常使用只需 USB 供電。

## 2. 車輛搜尋與登記（ESP-NOW）

學生車可用原本的 `PhoneBlockyMotorTuner.exe` 更新：新版「燒錄」分頁選「競賽學生車版（含裁判管制）」、選學生板 COM 埠，四個檔案保留勾選後燒錄；一般更新不要勾清除 flash。新版 EXE 已內建兩套學生韌體，舊 EXE 的教學版無裁判管制。詳見 [安裝教程](安裝教程.md)。此工具只供原 ESP32 小車板，S3 裁判仍使用上一節的專用環境。

1. 裁判登入、選 A 或 B 場並取得本場控制權，兩場皆清場回待賽時按「搜尋附近車輛」。搜尋持續 15 秒，最多顯示 32 台；名冊仍最多 64 隊，兩場共用登記結果。
2. 同頻道的學生車回報 MAC、原 AP 名稱與登記裁判。新車不需先按配對；搜尋本身不啟動或停止車輛。資料超過 5 秒會標示過期，需重新搜尋。
3. 在可登記車輛旁填入隊名，按「登記／配對」。等到「配對已確認」，再從本場名單勾選、準備比賽。配對會先停止該車，完成後回到教學待命，不自動執行舊動作。
4. 車已登記到另一裁判時，先由學生原頁按「允許更換裁判」，流程見下節。兩裁判同時配對時，車端只接受第一個有效請求；另一方不能覆蓋已完成的配對。

裁判與學生必須使用相同 2.4GHz 頻道（1–11）。若搜尋不到車，在學生原頁按「開放配對／設定頻道」（已配對車顯示「允許更換裁判」），填入裁判頁顯示的頻道。手機可能需要重新連接原學生 AP。這會停止該車、移除舊裁判配對並開放接管 60 秒。**目前沒有跨頻道自動搜尋**。

配對金鑰由兩板經 ECDH 推導，不在廣播中傳送金鑰；裁判收到帶金鑰確認碼的回覆才顯示成功。若顯示「配對未確認」，不等於車輛必定未寫入：先查看學生頁的裁判 MAC；可用準備本場確認 READY，或再次在學生頁開放並重新配對，不需清除 Flash。

同一塊裁判板的 A／B 場共享名冊，清場確認後可直接換場，不需重新配對。清場解除本場管制，但保留裁判配對。若另有一塊實體裁判板，學生只接受目前配對裁判的指令；改由另一塊管理仍需學生頁同意，不會共享名冊或自動移交。

### 裁判板故障／更換（不需 USB）

1. 確認學生車停止。授權仍在進行時不能更換；必要時先按學生頁的「停止本車」。原裁判失聯則等待租約失效並顯示故障停車。
2. 手機連自己的學生 AP，開原網頁，按「允許更換裁判」，輸入新裁判頁顯示的頻道並確認。
3. 車端先停止全部輸出與執行中的程式，保存鎖定狀態，再移除舊裁判配對。看到「開放接管」倒數後，新裁判按搜尋、選車、填隊名並配對。
4. 配對確認後，學生頁顯示新裁判 MAC 並回到教學待命；新裁判仍需準備及開始本場才授權比賽。

開放逾時、接管中斷電或 NVS 寫入失敗時，維持鎖定，不自動回教學或重新開放。重新連學生頁再操作即可。**學生存檔、Wi-Fi、PID 及 GPIO 設定保留**；只有裁判配對／比賽管制與場地頻道變更。接管當下不自動執行存檔；原 autorun 偏好也保留，日後正常重開機仍依原設定執行。

### USB 備援與進階設定

USB 保留首次燒錄、查詢本機登入資訊、除錯與特殊 GPIO 登記用途；以下既有配對工具仍可作備援，只能用於未受管制的車。沒有新增 `competition_release` USB 解鎖指令。

Python 環境需要 `pyserial`。關閉占用序列埠的監視器後執行：

```powershell
python tools/competition_pair.py --referee COM5 --student COM6 --name "A 隊" --show-credentials
```

工具會檢查角色、讀取 STA MAC、產生每車隨機金鑰、寫入兩板 NVS，並在裁判名冊登記隊名。STA 裁判必須先連上路由器，工具自動採用實際頻道設定學生車；若仍指定 `--channel`，必須與路由器相同。裁判不接受 USB 強制換頻。同一 MAC 再配對會更新該隊，不建立重複記錄。金鑰不保存至本機檔案。完成後重新啟動兩塊板；換下一個學生板重複操作即可。

`--show-credentials` 會在本機終端顯示裁判 IP 與裁判網頁操作密碼，以及學生 AP 名稱／密碼。裁判操作密碼與路由器 Wi-Fi 密碼是兩個不同用途；工具不回傳路由器密碼。學生保留原 AP 名稱與密碼，不需另登入一個競賽控制頁。不要把這段輸出貼進 repo。只要查看原有板子的連線資料：

```powershell
python tools/competition_pair.py --info COM5 --show-credentials
```

不加 `--show-credentials` 時不輸出密碼。若中途寫入失敗，重新執行整個配對命令，不要只更新其中一板。

裁判連接路由器，同時提供帶 STA IP 的 AP。手機／電腦可連同一可互通的路由器網路，或直接連裁判 AP。學生板繼續提供原 AP，不需持有路由器密碼。搜尋與公開金鑰交換使用廣播；配對確認與本場控制使用加密單播。

路由器請使用固定 2.4GHz 頻道 1–11，避免賽中自動換頻。兩塊裁判板若需共同看見同一批車，必須位於相同無線頻道；僅 SSID 相同、實際連到不同頻道的基地台，不保證互通。跨頻道搜尋與學生自動跟隨屬後續無線探索工作。

## 3. 學生準備與操作

手機連接原學生板的 `ESP32-…` 或自訂名稱，使用原密碼，瀏覽 `http://192.168.4.1/`。操作原本的首頁、Blockly 與搖桿。已配對但尚未被裁判選入本場時，仍可使用原教學功能。

選入本場並按「準備」後，各原頁面頂端顯示裁判狀態、模式階段及剩餘秒數；搖桿在手動授權時可用，自動、暫停、換段、結束與故障時鎖定。每次換段／恢復先放開搖桿與開關回到中立，再重新操作，舊的按住狀態不會延續。每階段第一個有效手動指令取得該車操控權。原緊急停止與共用狀態列的「停止本車」都會停止車輛並向裁判回報故障。

自動程式：賽前在原 Blockly 將程式「儲存到 ESP32」。裁判準備時驗證並鎖定快照；管制中執行／存檔按鈕鎖定，仍可編輯積木與下載到本機。混合模式即使先手動，也需先存好自動程式。未參賽時直接執行與 autorun 保持原行為；管制中重開機不執行 autorun。

自動階段被裁判暫停後，恢復會從 setup 重新執行，保留該階段剩餘時間。此規則已於 2026-11-03 由使用者確認定案；賽前需向裁判與參賽者說明。請勿假設能從原本 delay、迴圈或副程式的位置接續。

頂層 Blockly loop 每圈完成後至少等待 10ms 才再執行，對齊教學版節奏；閉迴路所有呼叫入口也共用至少 10ms 的更新間隔。10–100ms 使用實際時間差；超過 100ms 視為重新開始，重設時間基準並跳過該步，至少再等 10ms 才恢復更新，避免閒置後起步把整段等待算入積分與加速斜坡。通訊外層仍每圈 `delay(1)`，長程式由既有 service hook 服務；感測器與 OLED 等阻塞成本仍存在。需要計時請使用 millis／delay，不以 loop 圈數當精確時鐘。

未參賽時可直接在原設定頁、hardware_test 或 USB 調校，不需換回其他韌體。裁判管制中，USB 動作、硬體檢測與設定寫入均被韌體拒絕；讀取馬達狀態仍可用。即使舊網頁未更新，也不能繞過韌體授權。I2C 從機版維持獨立，不與裁判管制同時啟用。

### 選用 GPIO 輸出

第一版預設不允許自動程式使用一般 GPIO 作致動輸出。需要時可在無活躍比賽時透過 USB JSON 登記安全電位為 LOW 的腳位：

```json
{"cmd":"competition_outputs","pins":[15,32]}
```

允許登記 4、15、18、26、32；完成後重開機。這些腳位會在開機／撤權時拉低，請勿把原本需要輸入或上拉的感測器腳位誤登記為輸出。超音波固定 TRIG 2／ECHO 33，不能任意改到馬達或舵機腳位。舵機撤權時取消脈波，不回 90°；實際機構在失去脈波後的行為必須另測。

## 4. 裁判操作

裁判電腦或手機可連接現場路由器、瀏覽 `http://<裁判板的 STA IP>/`，也可直接連裁判 AP、瀏覽 `http://192.168.4.1/`。所有裝置使用同一入口，輸入裁判操作密碼，驗證成功後選 **A 場裁判／B 場裁判／中央音效台**。A、B 場各自按「取得本場控制權」；喇叭 PC 選音效台並按啟用，不需取得任何場的操作權。

STA IP 直接出現在 AP 名稱，也可由 DHCP 清單、115200 序列訊息或 `competition_info` 查詢。A、B 場獨立計時、模式、操作權與參賽名單；兩場合計最多 4 台車，適合兩場各 2 台。另一場正在使用的車會顯示場別且不能勾選，需等清場確認後才能轉場。搜尋與登記共用，僅兩場皆清場回待賽時可用；比賽前先完成車輛登記。

每個頁面有獨立操作者識別，同場其他頁只觀看。重新整理後需重新取得本場控制權，原控制權最多約 10 秒後可接手；兩場計時繼續。一般停止只影響本場；「全場緊急停止」展開後可另外確認停止 A、B 兩場。操作密碼僅保留在分頁 sessionStorage；登出此頁清除該分頁的密碼，不會遠端登出其他裝置。

1. 勾選本場隊伍。未勾選車不受本場操作影響。
2. 選手動、自動或混合；混合可選先手動或先自動。
3. 設定時間：手動／自動各預設 30 秒，中間暫停預設 5 秒。
4. 按「準備本場」，等待每車時鐘同步、程式驗證與 READY。
5. 確認「中央音效台已連線」，或在接喇叭的裁判頁按「本機接回音效」。無音效時可明確勾選「本頁靜音／允許無音效開始」。
6. 按開始。所有參賽板先確認共同啟動排程，約 1.2 秒後進第一段。
7. 混合模式在第一段結束後全車停止，間隔倒數完自動切入第二段。
8. 正常結束或中止後，等待每車回覆「輸出已鎖定」，再按清場／下一場；等各車確認解除管制後回到待賽。學生頁回到一般教學，舊程式／舊動作不自動重跑。

「裁判暫停」一定等待裁判按繼續；「階段間暫停」會自動繼續。恢復時另有約 1.2 秒準備窗口；若在 GAP 暫停，窗口結束後再消耗保存的 GAP 剩餘時間。

關閉裁判操作網頁不改變主控板計時；中央音效台已連線時仍會播放。本機播放模式則隨該頁關閉而停止。裁判板斷電、學生板重啟、換頻、租約逾時或同步失效都會使輸出鎖定，且不會因遲到封包自行恢復。

STA 斷線、重新連線（即使回到同頻道）或換頻時，兩場中仍活躍的比賽都改為故障，停止續租。路由器連線會重試，但比賽不自動重跑。若路由器改頻導致學生無法收到停止確認／清場，先恢復原場地頻道，取得停車確認後再清場；未確認前不可假報解除管制。

管制狀態保存在學生板 NVS，拔電不會解除。若裁判重開機而遺失本場名單，重新選入這些車、準備並中止本場，再等停止確認後清場。正常流程由原裁判送出終局清場指令返回教學；清場封包遺失會持續重送，不會假報成功。原裁判故障無法使用時，改走第 2 節的學生頁同意／新裁判接管流程。

**無線接收佇列溢位需要重開故障板。** 此旗標會鎖定到重開機，按繼續、清場或建立新比賽均不能解除。先停止本場、確認所有車已安全停止並排查封包過量／主迴圈阻塞，再重新啟動發生溢位的裁判板或學生板；無法辨識是哪塊時，安全停車後重開本場全部板子。之後重新準備一場並等待每車 READY，不延續故障前的比賽；反覆發生時停止使用並排查原因。

時間、模式與勾選名單目前屬本次開機的操作設定，重新開機回預設；隊伍、配對、頻道、密碼與 GPIO 設定存在 NVS。停止未收到回覆時畫面保持未確認，不能假報已停，也不能直接清場。

## 5. 音效與驗收

repo 不再提供 Team 254 的四個 WAV，也不自動下載。上游條款對使用與轉散布有不同限制，本專案未取得另外的轉散布許可；來源與雜湊僅留作歷史紀錄，見 [音效說明](../referee_data/audio/README.md)。2026-11-03 已另經使用者授權改寫 main 的相關歷史；託管服務快取與他人副本不在本次清除範圍。

喇叭 PC 開啟與裁判手機相同的裁判板網址，登入後選「中央音效台」，按「啟用中央音效」。四檔載入成功後中央自動取得播放權，A／B 裁判頁自動靜音，操作權仍由各場裁判持有。A／B 音效立即播放、允許重疊；不用排隊等待另一場播完。不需 Python、不需另填兩個裁判 IP。

中央失去心跳 5 秒後顯示離線，比賽照常計時；本機不會自行出聲，需裁判按「本機接回音效」。中央重連自動接回且不補播舊事件。瀏覽器必須先按一次啟用音訊，保持中央網頁開啟，避免 PC 休眠。

由操作者確認使用許可，在本機 `referee_data/audio/` 提供 `start.wav`、`resume.wav`、`end.wav`、`abort.wav`。中央與本機備援都從裁判板載入音檔，須執行裁判角色的 `buildfs` 與 `uploadfs`，將本機音檔放進板子的 LittleFS；不要發布這些映像。也可提供適當授權的替代錄音，但不能稱其為 FRC 原版。本機 WAV 已列入 `.gitignore`。沒有音效時勾選「本頁靜音／允許無音效開始」；此選項不會關閉中央喇叭。

目前驗證包括原有 Python／Node 回歸、新增前端假環境測試、實際 C++ 核心的假時鐘／故障注入，以及四角色編譯與兩個檔案系統建置。以下是上板後才能完成的驗收：

- A／B 各兩台車同時運作的啟停差、無線遺失下的最壞停止時間；A 場暫停／停止／清場期間 B 場保持運行，清場前不能跨場選同車。
- 裁判斷電、學生板重啟、未參賽車與鄰場控制器隔離。
- 兩裁判同時搜尋／配對、接管窗口逾時／重開機、配對確認遺失重送、舊裁判復電不能再控制，以及變更頻道後手機重新連線。
- 馬達慣性、舵機停脈波、長 delay／while／超音波／OLED 下的停止。
- 真實手機、音效授權、喇叭輸出及至少 30 分鐘負載運行。

工程目標與完整案例見 [SDD](espnow_competition_sdd.md)。尚未量測的 30／50／400 ms 數字不是已證實能力。

## 僅計時／音效（無 ESP-NOW 控車）

各場取得控制權後，在「本場設定 → 控制方式」選「僅計時／音效」，可填本場隊伍文字（選填），再設定手動、自動或混合及各段時間，按準備與開始。不需登記 MAC、配對、READY 回覆或路由器連線；手機仍需連上裁判 AP 或同網路才能操作。中央喇叭頁的使用方式不變，須由操作者啟用音效。

此模式的開始、暫停、換段、結束與停止只處理賽程和音效，**不會啟動或停止車輛**，須由現場人員控制車輛。A／B 場可各自選用不同控制方式；另一場若使用 ESP-NOW，仍維持其無線控制。

控制方式只能在清場後的待賽狀態選擇。原 ESP-NOW 場故障且尚未收到解除管制回覆時，不能切換以繞過清場；可先用另一個空閒場計時，原場車輛仍須依故障復原流程解除。純計時不受 ESP-NOW 初始化／佇列故障或 STA 斷線影響；瀏覽器失聯期間仍持續板上計時，音效只播線上收到的新事件，不補播離線事件。這次只需更新裁判韌體與 referee_data 網頁，學生不需更新。

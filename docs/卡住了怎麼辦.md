# 卡住了怎麼辦

> 自學課程的診斷手冊。**以 [硬體功能檢測頁](../data/hardware_test.html) 的檢測項目為索引**——
> 先讓自檢頁告訴你是哪一項不過，再翻到這裡對應的段落。
>
> 接線是固定的，所以絕大多數問題只有一種成因。照著二分法走，不要跳步驟。

---

## 怎麼用這份文件

1. 手機連上板子 → 開 `192.168.4.1` → 進入 **🔧 硬體功能檢測**
2. 按「🚀 開始全部檢測」，或用「✅ 開始勾選檢測」只重測有問題的那一項
3. 看哪一項卡住 → 回來查對應章節

檢測頁共 **9 項**：M1、M2、M3(+編碼器)、M4(+編碼器)、舵機 S1/S2、樂高按鈕、超音波、數位讀值、類比讀值。

> **重要觀念**：檢測頁不會自己判定通過，它跑完動作後會問你「是否正常？」。
> 你才是感測器——請真的盯著馬達看，不要習慣性按「✅ 是」。

## 0. 還沒進到自檢頁面

### 0-1 手機 WiFi 清單找不到 `ESP32-` 開頭的熱點

熱點名稱是 `ESP32-` 加上板子 MAC 位址的末四碼（例如 `ESP32-3A7C`），預設密碼 `12345678`。

| 二分法 | 做法 |
|---|---|
| ① 板子有沒有電？ | 板載電源燈是否亮 |
| ② 韌體有沒有燒進去？ | 接 USB 開序列監視器（115200 baud），開機應印出 AP IP 與 AP MAC |
| ③ 四個 bin 有沒有全燒？ | 用 `PhoneBlockyMotorTuner.exe` 的「燒錄」分頁重燒，並勾選「燒錄前清除 flash」 |
| ④ 手機看不到但別台看得到？ | 部分手機對 2.4GHz 通道敏感，換一台裝置確認 |

> 如果序列監視器完全沒有輸出，問題在燒錄，不在 WiFi——回 [安裝教程](安裝教程.md)。

**熱點名稱不是 `ESP32-` 開頭？** 如果你（或前一個使用者）在設定頁改過控制板名稱並填了路由器 WiFi，
熱點名稱會變成 `<你取的名字>-<取得的IP>`（例如 `66-192.168.1.23`）。這是正常的，不是故障。

### 0-2 連上熱點了，但 `192.168.4.1` 打不開 / 打開是空白

熱點是韌體開的，網頁是另外燒進 LittleFS 的。**熱點正常不代表網頁燒過了。**

> **九成是 `littlefs.bin` 沒燒。** 用 `PhoneBlockyMotorTuner.exe` 的「燒錄」分頁，
> 確認四個檔（`bootloader` / `partitions` / `firmware` / **`littlefs`**）**全部勾選**再燒一次。
>
> 開發者用 PlatformIO 的話，`pio run -t upload` 只燒韌體，網頁要另外跑 `pio run -t uploadfs`。

其他可能：

- 網址列被當成搜尋關鍵字 → 完整輸入 `http://192.168.4.1`
- 用了 `https://` → 這裡只有 http

### 0-3 網頁打得開，但顯示「🔴 WebSocket 未連接」

**這一條是初學者最常卡的地方，而且原因通常不在板子。**

| 順序 | 檢查 |
|---|---|
| ① | **手機的行動網路關掉**。Android 偵測到這個熱點「沒有網際網路」時，會自動把流量切回行動數據，導致網頁載得出來（快取）但 WebSocket 連不上 |
| ② | 系統跳出「此網路無網際網路連線，是否保持連線？」→ 選 **保持／仍要使用** |
| ③ | 同時最多只能連 **4 台裝置**（`WiFi.softAP(..., 1, 0, 4)`）。教室多人時，請別人先斷線 |
| ④ | 按頁面上的「🔄 重新連線」鈕 |
| ⑤ | 板子重開機 |

## 1. 馬達（M1 / M2 / M3 / M4）

自檢時每顆馬達會自動跑：**正轉由慢加速到極速 → 停 → 反轉由慢加速到極速 → 停**。

### 1-1 四顆馬達全都不動

先分清楚是「沒電」還是「沒訊號」：

| 二分法 | 判準 |
|---|---|
| ① 馬達驅動板有沒有獨立供電？ | ESP32 的 USB 電源**不足以驅動馬達**。驅動板必須外接電源 |
| ② 外接電源電流夠不夠？ | 電流不足的症狀最像「程式壞了」：馬達抽動一下、板子重開機、WiFi 斷線。**這是自組最常見的殺手** |
| ③ 共地了嗎？ | 外接電源的 GND 必須與 ESP32 的 GND 相連 |
| ④ WebSocket 有連上嗎？ | 指令根本沒送到，見 0-3 |

> **馬達一動板子就重開機** = 電源電流不足，不是程式問題。

### 1-2 某一顆不動，其他正常

排除了電源問題，就只剩該顆的接線。

- 檢查該馬達接到驅動板的兩條線（樂高 RJ12 的 **白 = MA0 / 黑 = MA1**）
- 把該馬達拔下來，接到另一個確定正常的通道 → 如果換位置後正常，問題在驅動板該通道；如果一樣不動，問題在馬達或線
- 對照 [接線說明頁](../data/wiring.html) 的樂高接頭區塊

### 1-3 會轉，但方向相反

**這不是壞掉。** 直流馬達的兩條電源線對調，轉向就相反。

- 把該馬達的 **白／黑** 兩線對調即可
- 或者接受它，之後在程式裡用負的 `duty` — 但**不建議**，因為方向的一致性正是這塊板要交出去的東西之一

> ⚠️ 如果你對調了白／黑，**編碼器的計數方向也會跟著與馬達轉向相反**，見 2-3。

### 1-4 會轉但很沒力 / 轉一下就停

- 電源電流不足（同 1-1 ②）
- 機構卡住：把馬達從機構上拆下來空轉測試，能分辨是電控問題還是機構問題

## 2. 編碼器（只有 M3 / M4 有）

自檢時 M3/M4 除了跑馬達動作，還會即時顯示 **編碼器 ticks**，並在最後給你「計數範圍」與「總變化量」。

### 2-1 馬達會轉，但 ticks 完全不變 ⚠️ 最常見

馬達的動力線和編碼器的訊號線是**完全獨立的兩組**。馬達會轉，只證明動力線接對了，
跟編碼器一點關係都沒有。所以這個症狀的範圍很明確——**問題一定在那四條編碼器線上**。

依序檢查：

| 順序 | 檢查 | 樂高 RJ12 對應 |
|---|---|---|
| ① | 編碼器有沒有**供電** | 🟩 **綠線 = VCC（4.3–5V）** |
| ② | 編碼器有沒有**共地** | 🟥 **紅線 = GND** ← 紅色是地，不是電源 |
| ③ | A/B 相接對腳位 | 🟨 **黃 = A 相**（M3→GPIO **35**、M4→GPIO **36**）<br>🟦 **藍 = B 相**（M3→GPIO **34**、M4→GPIO **39**） |
| ④ | 線有沒有接牢 | 杜邦線鬆脫、RJ12 沒卡到底 |

> 🚨 ①②最容易錯，因為**樂高的紅線是接地、綠線才是電源**，和直覺相反。接反了編碼器不會動作。

**不需要接上拉電阻。** 樂高編碼器是主動輸出（推挽），高低電位自己都會拉。
韌體端用的也是純輸入（`pinMode(pinA, INPUT)`），沒有要求上拉。

> **例外**：若你換成**開集極輸出**的非樂高編碼器，就必須外接 `3.3V ──[10kΩ]── 訊號腳`（四組），
> 而且只能外接——GPIO 34/35/36/39 在晶片層級沒有內部上拉，`INPUT_PULLUP` 對它們是空操作。

> 🚨 **樂高線色的陷阱**：這條線的 **紅色是 GND、綠色才是 VCC**，和一般人的直覺相反。
> 接反了編碼器不會動作，嚴重時會燒。接之前務必看 [接線說明頁](../data/wiring.html) 的線色對照表。

### 2-2 ticks 會變，但數值亂跳、馬達停了還在跳

訊號受干擾：

- 編碼器的 GND 是否與 ESP32 **共地**（紅線）——沒有共同參考點，訊號就會飄
- **馬達動力線與編碼器訊號線分開走**，不要綑在一起。馬達是很強的雜訊源
- 線材過長或用了品質差的延長線
- 電源電流不足時也會造成訊號不穩（見 1-1 ②）

> 韌體已開啟 PCNT 硬體濾波（`pcnt_set_filter_value(unit, 100)`）擋短脈衝雜訊，
> 若仍然亂跳，問題出在接線或電源，不是程式。

### 2-3 ticks 會變，但方向和馬達轉向相反

正轉時 ticks 應該變大。如果相反：

- 把該馬達編碼器的 **黃／藍**（A/B 相）兩線對調
- 或者你在 1-3 對調過馬達的白／黑 → 兩者要一起改，保持「正轉 = ticks 增加」

### 2-4 ticks 會變，但轉一圈的數字對不上

預設值下，**輸出軸轉一圈 ≈ 720 ticks**（`TICKS_PER_DEGREE = 2.0`）：

```
ENCODER_PPR (360) × ENCODER_MODE (2X 解碼) ÷ 360° = 每度 2 ticks
```

如果你用的不是樂高 NXT 馬達，這個數字就會不對。到 **設定頁（`set.html`）→ 硬體參數** 修改：

| 馬達類型 | 編碼器位置 | PPR | 減速比 |
|---|---|---|---|
| 樂高 NXT/EV3 | 輸出軸 | 360 | — |
| 一般霍爾編碼馬達 | 馬達軸 | 22 | 21.3 |

改完要用管理密碼寫入 NVS 才會保存。相關定義見 [include/config.h](../include/config.h)。

## 3. 舵機 S1 / S2

自檢會讓 S1 掃描 0° → 90° → 180° → 回中，接著換 S2。

| 症狀 | 檢查 |
|---|---|
| 完全不動 | 訊號線是否接在 **S1 = GPIO 5、S2 = GPIO 13** |
| 抖動、嗡嗡叫、轉不到位 | **舵機供電不足**。舵機瞬間電流很大，不要從 ESP32 的 5V 取電，請獨立供電並與 ESP32 共地 |
| 只有一顆會動 | 兩顆對調位置測試，分辨是舵機壞還是腳位問題 |
| 轉到底發出卡死聲 | 機構行程超過舵機範圍，先把舵機從機構上拆下來單獨測 |

指令格式：`{"cmd":"servo","ch":1,"deg":90}`，角度 0–180°。

## 4. 感測器

### 4-1 樂高按鈕（GPIO 4）值不變

- 該腳位是 `INPUT_PULLUP`：**沒按下時讀到 1，按下時讀到 0**。如果你預期相反，那是正常的
- 按鈕另一端要接 **GND**，不是 3.3V
- 自檢頁會同時顯示「初始值」與「按下時」，兩個數字要不一樣才算通過

### 4-2 超音波距離固定不變 / 一直是 0

- **Trig = GPIO 2、Echo = GPIO 33**，對調了就量不到
- HC-SR04 需要 **5V** 供電，接 3.3V 會不穩或完全不動
- ⚠️ HC-SR04 的 Echo 輸出是 **5V**，而 GPIO 33 不耐 5V。建議加分壓電阻（Echo → 1kΩ → GPIO33 → 2kΩ → GND）再接
- 測試時手掌要在感測器**正前方**前後移動，距離太近（< 2cm）量不到

> GPIO 2 同時是板載 LED，開機瞬間為低電位——這是正常的，不影響超音波。

### 4-3 數位讀值（GPIO 15）沒反應

- GPIO 15 是 **strapping pin**：**開機瞬間不要把它強拉到低電位**，否則板子可能進不了正常開機模式
- 先把感測器拔掉重開機，確認板子會正常啟動，再插回去測

### 4-4 類比讀值（GPIO 32）讀不到變化

- 讀值範圍 **0–4095**
- 確認感測器是類比輸出（有些模組只有數位輸出腳）
- 供電與共地

## 5. 之後的課程才會遇到的

### 5-1 `move_to` / `move_by` / `speed` 沒反應，回傳 `no_encoder`

**這不是錯誤，是設計。**

M1/M2 沒有編碼器，做不到閉迴路。韌體會直接回：

```json
{"ok": false, "err": "no_encoder"}
```

角度與轉速控制**只有 M3/M4 支援**。M1/M2 只能用 `pwm`。

> 這是刻意的：與其讓它默默轉得不對，不如明講做不到。

### 5-2 馬達到位後停不下來，一直微微抖動

到位後會進入**角度保持**，用閉迴路持續修正——你用手推它，它會夾回去。這是正常行為。

抖動太明顯時，到設定頁（`set.html`）→ **角度保持 (Hold)** 調整：

| 參數 | 預設 | 意義 |
|---|---|---|
| `holdSettleDeg` | 1.5° | 死區。進到這個誤差內就放鬆。**抖動時先調大這個** |
| `holdKi` | 8.0 | 卡住時加力的快慢 |
| `holdMaxDuty` | 60 | 夾持力上限 PWM% |

要**完全解除保持**：對該馬達下 `stop`（或改下 `pwm` / `speed` 切換模式）。詳見 [角度保持.md](角度保持.md)。

### 5-3 積木程式送出去沒反應

- 看 WebSocket 是否為「已連線」
- `loop` 是空的 → 只有 `setup` 會跑一次
- `loop` 裡沒有 `delay` → 跑太快看不出來，先加一個 `delay 1000`

## 還是解決不了？

回報時請附上這四項，會省下大量往返：

1. **自檢頁哪一項不過**（截圖最好）
2. 該項顯示的數值（編碼器計數範圍、距離範圍、讀值…）
3. 序列監視器（115200 baud）的輸出
4. 你的馬達與電源型號

# 拍攝規範

> 錄影開始前必讀。這份文件的目的是讓 30 支影片看起來像同一門課，
> 以及讓學員在手機上看得清楚每一個「成功訊號」。

---

## 0. 一句話原則

**觀眾在手機上看。畫面上任何他需要判讀的東西（編碼器數字、綠燈、按鈕），
在 6 吋螢幕上必須一眼可讀。** 這條原則凌駕所有美感考量。

---

## 1. 交付規格

| 項目 | 規格 | 說明 |
|---|---|---|
| 解析度 | **1920×1080 (1080p)** | 不要拍 4K。這門課沒有任何畫面受益於 4K，但檔案大 4 倍、剪輯卡頓、上傳慢 |
| 影格率 | **30 fps**（全片統一） | 唯一例外見下方「慢動作」 |
| 編碼 | H.264 / MP4，8–12 Mbps | YouTube 上傳後會重壓，來源給足即可 |
| 色彩 | Rec.709 / SDR | 不要開 HDR 或 LOG，手機端顯示會發灰 |
| 音訊 | 48 kHz，AAC 192 kbps，**立體聲但內容為單聲道對齊** | 只用單邊聲道是最常見的低級錯誤 |
| 響度 | **-14 LUFS**，峰值 ≤ -1 dBTP | YouTube 標準 |
| 片長 | 依各集腳本標示 | E05 例外允許 10 分鐘 |

### 為什麼不拍 4K

有人會說「4K 拍、1080 出，可以裁切」。這門課用不到：畫面內容是手機 UI 和
馬達特寫，兩者都用固定機位，不需要後製重構圖。省下來的時間拿去重拍一次
比較划算。

### 慢動作（唯一的例外）

只有兩種鏡頭建議用 **60 fps 拍、放到 30 fps 時間軸做 50% 慢動作**：

1. S3「用手推它，它自己夾回來」——回彈過程太快，正常速度看不出來
2. S1「同樣 30%，兩顆馬達不一樣快」——並排比較需要放慢

其餘一律 30 fps 直出，**不要混拍**。

## 2. 版面：固定雙畫面模板

這是本課程的視覺骨架，**所有操作類影片都用它**。

```
┌───────────┬────────────────────────────────┐
│           │                                │
│   手機    │                                │
│   螢幕    │        硬體實拍特寫             │
│  (直式)   │                                │
│           │                                │
│  607×1080 │           1313×1080            │
└───────────┴────────────────────────────────┘
              1920×1080
```

| 區塊 | 尺寸 | 來源 |
|---|---|---|
| 左：手機螢幕 | 607×1080（9:16 滿高） | 手機內建螢幕錄影 |
| 右：硬體 | 1313×1080 | 相機／webcam 固定機位 |

**為什麼一定要雙畫面**：課程的每一個「成功訊號」都是
「我在手機上做了 A，硬體發生了 B」的因果。切鏡頭會切斷因果，
學員只會記得兩個獨立畫面。E05 的編碼器段落尤其不可切鏡。

**可以破格的時候**：

- 純講解、沒有硬體動作 → 全螢幕手機或全螢幕字卡
- E02 燒錄（電腦畫面）→ 全螢幕電腦錄影，不需要硬體視角
- 需要看清楚接線細節 → 全螢幕硬體特寫

### 手機螢幕怎麼進畫面

**不要用相機翻拍手機**（摩爾紋、反光、對焦呼吸，且看不清數字）。用內建錄影：

- Android：下拉快捷 → 螢幕錄影
- iOS：控制中心 → 螢幕錄製

錄出來是 1080×2400 之類的長條，剪輯時**等比縮放到高度 1080**，
左右超出的部分裁掉（手機 UI 是置中的，裁邊不影響）。

## 3. 錄影前檢查清單（手機）

這一段每次錄之前照著跑一遍，補錄成本很高。

- [ ] **開啟「顯示點按操作」**（Android：開發者選項 → 顯示點選操作）
      ← **最重要的一項**。沒有它，觀眾看不到你按哪裡、拖多遠，
      整堂「拖滑桿」的課會變成畫面自己在動
- [ ] iOS 沒有這個功能 → 剪輯時手動加圓點動畫，或改用 Android 錄
- [ ] 開啟**勿擾模式**，關閉所有通知橫幅
- [ ] 電量顯示 > 50%（低電量紅色圖示很分心）
- [ ] 螢幕亮度固定，關閉自動亮度（避免中途變暗）
- [ ] 關閉自動旋轉
- [ ] 螢幕自動鎖定改成「永不」
- [ ] **關閉行動網路**（這門課要連 ESP32 熱點，開著行動網路是 § 0-3 的頭號卡點，
      示範時也不該有例外）
- [ ] 手機桌布／通知列不要有個資（真實姓名、其他 WiFi SSID）

### 隱私：發布前必查

| 畫面 | 風險 | 做法 |
|---|---|---|
| `set.html` | 會顯示 **WiFi SSID、密碼、管理員密碼** | 錄影前把密碼改成示範值（如 `demo1234`），錄完再改回 |
| WiFi 清單 | 會列出你家/公司的所有 SSID | 錄影時只拍 `ESP32-` 那一列，或事後打碼 |
| 電腦畫面（E02） | 檔案總管路徑含使用者名稱 | 用乾淨的示範資料夾，或視窗最大化蓋掉 |

板子的 `ESP32-DB50`（MAC 末四碼）**可以露出**，那是課程內容的一部分。

## 4. 電腦畫面錄影（僅 E02）

| 項目 | 設定 |
|---|---|
| 錄影範圍 | **視窗擷取**，不要錄整個桌面 |
| 顯示縮放 | 錄影前把 Windows 縮放調到 **150%** |
| 解析度 | 1920×1080，畫面會因縮放而字大 |
| 游標 | 開啟游標高亮／點擊效果（OBS 或 ShareX 都有） |

**縮放 150% 是關鍵**。燒錄工具的 log 區、COM 埠下拉選單在 100% 縮放下，
壓到 1080p 再上傳 YouTube 後幾乎無法辨識。寧可畫面元素只裝得下一半，
也不要讓學員看不清楚 `0x1B9000` 是什麼。

## 5. 硬體實拍

### 機位

- **固定機位，不要手持。** 手機夾臂或三腳架，全課程同一個角度
- 高度：略高於桌面，約 30–45 度俯角
- 距離：M3 馬達與編碼器要能填滿畫面 1/3 以上

### 對焦與曝光

- **鎖定對焦與曝光**（點住畫面直到出現 AE/AF LOCK）
- 馬達轉動時自動對焦會來回拉風箱，這在特寫鏡頭裡非常明顯

### 燈光

- 桌面主光一盞（大面積柔光，避免鏡面反光打在 shield 上）
- **不要用日光燈或會頻閃的燈**，30 fps 下容易拍到滾動條紋
- 電子零件是深色的，比你以為的更需要光

### 背景

- 素色桌墊（深灰或墨綠），不要用木紋或格線
- 畫面裡不要有無關線材。**「線很亂」是這門課學員最大的恐懼**，
  你的示範桌面亂，他會覺得自己永遠做不到

## 6. 聲音

聲音的優先序高於畫面。畫面糊了還能看，聲音糊了會直接關掉。

### 三軌結構

| 軌 | 內容 | 音量 |
|---|---|---|
| 1 | **旁白**（事後配音） | 主軌，-14 LUFS |
| 2 | **現場環境音**（馬達聲、舵機聲、按鍵聲） | 旁白下 -18 dB，旁白空檔時抬到 -12 dB |
| 3 | 背景音樂 | 旁白下 -24 dB，或整段不用 |

### 為什麼旁白要事後配

現場有馬達在轉，你講話會被蓋掉，而且馬達是間歇性噪音，降噪工具處理不了。
**做法**：現場只錄畫面與環境音，講稿在安靜房間另外錄，剪輯時對齊。

腳本裡標了「這裡不要旁白，讓畫面說話 5 秒」的段落（E05 § 5），
那 5 秒**要讓馬達聲和編碼器跳動的畫面獨佔**，不要墊音樂。

### 麥克風

- 領夾麥（有線即可）或 USB 電容麥，距離嘴 15–20 cm
- **不要用相機/手機內建麥克風**錄旁白
- 錄音房間：關窗、關空調、地上鋪東西吸音

## 7. 字幕與螢幕文字

| 項目 | 規格 |
|---|---|
| 字幕字級 | **48–60 px** @1080p（畫面高度的 4.5–5.5%） |
| 最小可用字級 | 36 px。低於這個在手機上不可讀 |
| 字型 | 思源黑體 / Noto Sans TC，**Medium 或 Bold**，不要用 Light |
| 描邊 | 2–3 px 深色描邊或半透明底板（畫面背景會變） |
| 位置 | 距畫面底部 **≥ 130 px**（避開 YouTube 進度條與 CC 字幕） |
| 安全區 | 四邊各留 5% 不放重要內容 |

**必上字幕。** 機構組同事很可能在工廠、通勤、或不方便開聲音的地方看。
用 YouTube 自動字幕產出後**人工校對**——「編碼器」「舵機」「PWM」
「移動到」這些詞自動辨識錯誤率很高。

### 螢幕標註（圈選／箭頭）

腳本裡凡是寫「畫面：特寫某個東西」的地方，都要加標註：

- 圈選：2–3 px 螢光黃或橘色圓角矩形，**動畫進入**（0.3 秒），不要突然出現
- 全課程同一種顏色與粗細
- E05 那個編碼器數字，圈選後**停留 3 秒**（腳本已明確要求）

## 8. 固定六段結構的視覺對應

腳本規定每支片六段。給每一段一個固定的視覺標記，學員三集之後就能預期節奏：

| # | 段落 | 視覺處理 |
|---|---|---|
| 1 | 回扣 | 上一集的畫面，加 50% 白色遮罩 + 「上一集」角標 |
| 2 | 一個問題 | 全螢幕字卡，深色底，一句話 |
| 3 | 動手 | 雙畫面模板 |
| 4 | **成功訊號** | **固定綠色字卡**（見下方色票），左側列出可勾選項目 |
| 5 | 卡住了？ | 固定橘色字卡，列出症狀 → 指向診斷表章節編號 |
| 6 | 下一集鉤子 | 片尾模板 |

第 4、5 段的字卡**必須是固定模板**，只換文字。這兩段是錄播格式的生死線，
學員需要在滑動進度條時一眼認出「綠色的那塊就是我要對照的地方」。

## 9. 色彩識別

沿用課程本身的隱喻（自檢頁的紅綠燈）：

| 用途 | 色碼 | 說明 |
|---|---|---|
| 底色 | `#0B1220` | 近黑深藍，字卡背景 |
| 主色 | `#22C55E` | 綠 = 通過、成功訊號 |
| 警示 | `#F59E0B` | 橘 = 卡住了、注意事項 |
| 錯誤 | `#EF4444` | 紅 = 失敗、常見錯誤 |
| 文字 | `#F8FAFC` | 近白 |
| 次要文字 | `#94A3B8` | 灰藍 |

綠色的意義必須嚴格保留給「成功訊號」，不要拿去當裝飾色。

```
S0E05_自檢_主檔.mp4          ← 成品
S0E05_自檢_手機.mp4          ← 手機錄影原始檔
S0E05_自檢_硬體.mp4          ← 相機原始檔
S0E05_自檢_旁白.wav          ← 旁白原始檔
S0E05_自檢_縮圖.png
```

原始檔留著。這門課會迭代，重剪的機率比你以為的高。

## 11. 建議的錄製順序（不要照集數順序錄）

**先錄 E05 和 E06。**

理由有三：

1. 這兩集是課程的兩個核心指標（time-to-first-life / time-to-first-control），
   如果雙畫面模板在這兩集不成立，整套版面要重想 —— 早點發現比較好
2. **E00 需要用到成品畫面**（「手機拖一下，馬達就轉」「用手推它會夾回來」），
   那些素材要先拍出來才有得剪
3. 錄前兩集的時候你的口條和節奏還在調整，讓最重要的兩集享有第二次機會

順序建議：`E05 → E06 → E03 → E02 → E04 → E01 → E00`

## 12. 發布設定

| 項目 | 建議 |
|---|---|
| 平台 | YouTube（不公開清單或公開播放清單） |
| 章節標記 | **必加**。E05 十分鐘，沒有章節等於逼學員從頭看 |
| 縮圖 | 統一模板：左側大字集數（`E05`）+ 一行主題 + 右側該集關鍵畫面 |
| 說明欄 | 前三行放：本集成功訊號、對應診斷表連結、器材清單連結 |
| 播放清單 | 依季分（S0 上車 / S1 動 / …） |
| 置頂 | 另做一支 **60 秒成果影片**當播放清單封面，見下 |

### 建議補一支「60 秒成果片」

目前學員要看完 7 支片才走到「第一次指揮它」。建議另剪一支 60 秒的純成果
展示（無旁白或極簡旁白，只有畫面＋音樂），置於播放清單最前面與各頁面入口。
它的任務只有一個：**讓人相信這是真的、值得花 7 支片的時間**。
素材可以完全來自 E05／E06 的既有拍攝，不需要另外開機。

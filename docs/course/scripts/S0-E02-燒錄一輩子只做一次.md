# S0-E02｜燒錄：一輩子只做一次

**片長目標**：7–8 分鐘
**這集的一句話**：帶觀眾完成整門課唯一一次的韌體燒錄，並確認板子已經可以運作。

---

## 前提

- 零件已認完（E01）
- 需要一台 Windows 電腦（這是全課程唯一一次）
- 一條能傳輸資料的 USB 線

## 器材

- WeMos D1 R32 + 馬達驅動板（已插好，先不接馬達與外接電源）
- USB 線
- 電腦

---

## 旁白要點

### 1. 為什麼只有這一次需要電腦（0:00–1:00）

**畫面**：桌上只有板子、USB 線和一台電腦，馬達與電源都還沒接上。

> 「這一集是整門課唯一一次需要打開電腦。做完之後，你的程式都會在手機上完成，不用編譯、不用重新燒錄，也不用再插 USB 線。」
>
> 「原因是這塊板子裡面跑的，不是你寫的程式，而是一個能接收並執行指令的直譯器。直譯器只需要燒錄一次，之後我們替換的是送給它的指令，不是韌體本身。」

直譯器的架構是最後一季的選修內容。這裡只需要一句話交代「為什麼燒一次就夠」，不要展開。

### 2. 用打包好的工具，不用架開發環境（1:00–2:00）

**畫面**：雙擊 `PhoneBlockyMotorTuner.exe`，視窗開啟。

> 「燒錄用這一個工具就可以。你不需要安裝 Python，不需要安裝 PlatformIO，也不需要另外去找燒錄程式。四個韌體檔案已經包在這個執行檔裡面，雙擊就能開。」
>
> 「這類工具在業界叫做 Configurator——刷韌體、調參數、即時控制都在同一個視窗裡完成。玩無人機的人熟悉的 Betaflight Configurator，就是同一類的東西。」

### 3. 接上板子，確認 COM 埠（2:00–3:30）

**畫面**：USB 線插上板子，切到裝置管理員，畫面上出現新的 COM 埠。

> 「先用 USB 線把板子接到電腦。這個時候馬達和外接電源都還不用接。」
>
> 「接上之後，電腦應該會多出一個 COM 埠。如果你的電腦完全沒有反應，第一件要做的事是換一條 USB 線。」
>
> 「市面上有不少 USB 線只有電源線、沒有資料線。那種線可以充電，但電腦看不到裝置。先換線，再考慮驅動程式的問題。」

**畫面**：工具切到最右邊的「燒錄」分頁。

驅動程式（CH340 或 CP2102）確實也可能是原因，但換一條線的成本遠低於重裝驅動。這個順序要在片中講清楚。

### 4. 燒錄之前先按「斷線」（3:30–4:00）

**畫面**：明確指出上方連線列的「斷線」按鈕，按下去。

> 「這一步很容易漏掉。如果你剛才在最上面的連線列連過 USB，燒錄之前一定要先按「斷線」。」
>
> 「燒錄程式需要獨占那個 COM 埠。連線還開著的話，燒錄會失敗。」
>
> 「另外提醒一件事：燒錄分頁有自己的 COM 埠選單，和最上面那一列是兩個不同的地方。以燒錄分頁選到的為準。」

### 5. 確認四個檔案（4:00–5:30）

**畫面**：四列表格，預設都已勾選，位址已經填好。

> 「切到燒錄分頁之後，你會看到四個檔案，預設都已經勾選，位址也都填好了。」

| bin 檔 | 位址 | 內容 |
|---|---|---|
| `bootloader.bin` | `0x1000` | 開機載入器 |
| `partitions.bin` | `0x8000` | 分區表 |
| `firmware.bin` | `0x10000` | 主韌體 |
| `littlefs.bin` | `0x1B9000` | 網頁（手機上看到的所有畫面） |

> 「第一次燒錄，四個全部都要燒。」
>
> 「特別留意最後一個 `littlefs.bin`，那是你手機上會看到的所有網頁。韌體和網頁是分開的兩份檔案。只燒韌體、沒有燒網頁的話，熱點會正常出現，但網頁打不開。」
>
> 「位址已經預設帶好了，不要修改。」

「韌體和網頁是分開的」這件事，會在 E04 的診斷表再出現一次。這裡先說清楚，之後學員遇到空白網頁才知道要回哪一步。

### 6. 開始燒錄（5:30–6:30）

**畫面**：按下「開始燒錄」，下方訊息區開始輸出。

> 「按下開始燒錄，下面的訊息區就會開始跑。這個過程大約需要一到兩分鐘。」
>
> 「傳輸速率預設是 921600，這是最快的設定。如果過程中經常斷線或出現錯誤訊息，把它改成 460800 或 115200，速度慢一些，但穩定度比較高。」
>
> 「看到訊息顯示「燒錄完成，請重新啟動 ESP32」，就表示寫入成功了。」

### 7. 重新啟動（6:30–7:00）

**畫面**：按下板子上的 RST 鍵。

> 「最後按一下板子上的 RST 鍵，或者把 USB 重新插拔一次，讓板子重新開機。」

---

## 成功訊號

這集的驗收不是訊息區出現「燒錄完成」四個字，而是：

> 拿出手機打開 WiFi 清單，看到一個 `ESP32-` 開頭的熱點（例如 `ESP32-DB50`，後面四碼是這塊板子的 MAC 末四碼）。

看到熱點，就代表韌體已經在運作。

網頁有沒有燒進去，要到 E04 打開瀏覽器才知道。所以如果那時候畫面是空白的，回到這一集重燒 `littlefs.bin`。

## 常見卡點

| 症狀 | 首先檢查 |
|---|---|
| 電腦看不到 COM 埠 | 先換一條 USB 線（充電線沒有資料線）；再檢查 CH340 / CP2102 驅動 |
| 按「開始燒錄」沒有反應，或顯示埠被占用 | 沒有先按「斷線」；或序列監視器、其他程式正占用該埠 |
| 燒到一半出現 `A fatal error occurred` | 把傳輸速率降到 460800 或 115200；換一個 USB 埠，避開 USB hub |
| 燒完了但手機找不到熱點 | 確認四個檔案是否全部燒錄、位址有沒有被改到。可勾選「燒錄前清除 flash」重燒一次 |
| 板子之前燒壞、無法開機 | 勾選「燒錄前清除 flash」，整顆清空後再寫入 |

完整問答見 [安裝教程 § 常見問題](../../安裝教程.md)。

# 內建範例程式

積木頁（`blockly.html`）頂列的 **📚** 裡有幾支現成的程式，點一下就載入到畫布。
這些範例是給第一次用這塊板子的人看「一支能跑的程式長什麼樣」，不是最佳寫法。

## 怎麼用

1. 積木頁右上 **📚**。
2. 點任一支 → 畫布上的積木會被取代（畫面上有未存檔的修改時會先問），並自動「看全部」。
3. 按底列 **▶️ 執行** 就會跑（這一步只送到板子的記憶體，沒有存檔）。
4. 想讓它開機自動跑，要再按 **💾 存到 ESP32** 並打開 **⚡ 開機自動執行**。

**範例不會動到板子上存的那一支程式。** 範例檔放在 LittleFS（`data/examples/`），
板子上的存檔在 NVS（`prog` 分割區），兩者是不同地方 —— 板子上只存一支程式，
載入範例若去佔用它，等於把人家寫好的程式蓋掉。

積木上的 💬 圖示點開有說明文字（哪個數字可以改、改了會怎樣）。

### 01-motor-pwm — 轉一下、停一下

```
setup: 停止馬達 全部          ← 避免上一支程式還留著動力
loop:  馬達1 Forward 動力 50%
       延遲 1000 毫秒
       停止馬達 1
       延遲 1000 毫秒
```

可以改的地方：動力改 20 看馬達轉不轉得動（低動力起步會卡住，這是正常的）；
方向改 `Backward`；兩個延遲改成不一樣長。

### 02-servo-angle — 舵機轉到 90°

```
setup: 舵機1 角度 0          ← 每次執行都從同一個起點開始
loop:  舵機1 角度 90
       延遲 2000 毫秒
       舵機1 角度 0
       延遲 2000 毫秒
```

舵機接 S1（GPIO 5）或 S2（GPIO 13）。角度只能 **0–180°**，超出範圍韌體會夾住；
舵機靠自己的內部電路保持住位置，所以不需要編碼器，也沒有「設零點」這回事。

延遲不要設太短：舵機從 0° 轉到 90° 需要時間，上一個角度還沒到就送下一個，
看起來會像只抖了一下。


### 03-motor-reverse — 正轉反轉三次

```
setup: 停止馬達 全部
       重複 3 次
         馬達1 Forward 動力 50%
         延遲 1000 毫秒
         馬達1 Backward 動力 50%
         延遲 1000 毫秒
       停止馬達 1
loop:  （空的）
```

動作放在 setup，所以只跑一遍就停；loop 留空沒有問題。想一直重複的話，把
「重複」移到 loop 裡就行。

可以改的地方：次數 3 改成 5；兩個延遲改成不一樣長。延遲不要設 0，
否則正反轉切換太快，馬達根本來不及動。

### 04-motor-speed — M3 固定轉速

```
setup: 停止馬達 全部
loop:  馬達3 轉速 120 RPM
       延遲 4000 毫秒
       停止馬達 3
       延遲 2000 毫秒
```

`speed` 是**閉迴路**：韌體讀編碼器算出實際轉速，再自動調整動力去追目標。
`pwm` 則是固定給多少動力，用手按住輪子或負載變重時轉速會掉；`speed` 會自動
加大動力，讓轉速維持不變（超過馬達能力時當然還是會轉不動）。
所以只有有編碼器的 M3、M4 能用。

可以改的地方：120 改成 60 或 250（Blockly 只接受 60–250 的正數）；
接著換成 `pwm` 比較手按住輪子時的差別。

### 05-angle-hold — 轉到 90° 並保持

```
setup: 停止馬達 3
       設零點 馬達3          ← 「現在的位置」變成 0°
       馬達3 移到角度 90
loop:  （空的）
```

`move_to` 到位後不會停，而是進入**保持**：韌體用編碼器回授持續修正，
用手扳軸會被推回 90°，原理就是伺服機（細節見 [角度保持.md](角度保持.md)）。
要放開保持，對該馬達下**停止**（或改下 `pwm`／`speed`）。

動作放在 setup 只送一次。`move_to` 每次執行都會重新開始一次移動，
放在 loop 裡反覆送會一直打斷保持，沒有好處。

可以改的地方：90 改成 180 或 -90；保持的力道與死區在 set.html 調。

### 06-indexer-45 — 分度盤 45°

```
setup: 停止馬達 3
       設零點 馬達3
loop:  馬達3 相對轉 45°
       延遲 1500 毫秒
```

`move_by` 是「從**現在的位置**再轉多少度」，不是從上一個目標往下算。
上一步還沒到位就送下一個，會從半路開始算，結果少轉；所以延遲要夠長，
讓馬達先到位。轉得慢（負載重）就把 1500 加長。每轉 45° 一次，8 次剛好一圈，
到位後仍會保持在該角度。

可以改的地方：45 改成 90 或 -45（反方向）；延遲改短看看會不會少轉。

### 07-encoder-plot — 讀編碼器角度

```
setup: 停止馬達 3
       設零點 馬達3
loop:  繪圖 名稱「角度」 數值 = 馬達3 編碼器 角度(°)  單位 °
       延遲 100 毫秒
```

馬達是停止的，用手轉軸，到 **☰ → 開啟獨立 Plotter** 就能看到角度跟著變：
正轉為正、反轉為負。`encoder_read` 還可以選計數（ticks）或轉速（RPM）。
它回傳整數，之後可以拿去做判斷，例如「角度超過 90 就停」。

可以改的地方：下拉選單改成轉速；延遲 100 是取樣節拍，不要設成 0。

### 08-button-start — 按鈕才開始

```
setup: 停止馬達 全部
       直到 Lego按鈕(4) = 0 為止
         延遲 20 毫秒
       馬達1 Forward 動力 50%
       延遲 2000 毫秒
       停止馬達 1
loop:  （空的）
```

`until` 迴圈在條件成立前一直重複，成立才往下走，所以程式會停在「等按鈕」，
按下去才開始轉。按鈕腳（GPIO 4）韌體讀的時候是開上拉電阻的，所以**沒按是 1**；
按下時讀到 0 還是 1 看接線，常見是 0。接法相反就把 0 改成 1，
不確定先用「硬體檢測」頁看按下前後的數值。

等待迴圈裡的 `延遲 20` 是讓板子有空做別的事（控制節拍、接收新程式），不要拿掉。
放在 setup 只等一次；想「每按一次就跑一次」要改放 loop。

### 09-ir-line — 紅外線偵測停車

```
setup: 停止馬達 全部
loop:  如果 紅外線(數位) 腳位 15 = 1
         則 停止馬達 1
         否則 馬達1 Forward 動力 40%
       延遲 50 毫秒
```

`ir_digital` 回 0 或 1（有沒有偵測到）。哪個值代表「偵測到」依模組而定，
同一個模組在黑線上和白底上也不一樣，所以先用「硬體檢測」頁看過讀值再決定。
這支先做最簡單的「看到就停」；要做成兩顆馬達的循跡，等學會條件判斷再延伸。

可以改的地方：1 改成 0 反過來；40 改成別的動力；延遲不要設 0。

### 10-knob-servo — 旋鈕控制舵機

```
setup: 舵機1 角度 90
loop:  舵機1 角度 = 對應(類比讀取 腳位 32, 0–4095 → 0–180)
       延遲 50 毫秒
```

`analogRead` 回 0–4095，舵機只收 0–180°，中間用 `map`（對應）換算。
`map` 不會夾限，所以旋鈕要接在 0–3.3V 之間；範圍外的值韌體會把舵機角度夾住。
GPIO 32 是 ADC 腳，WiFi 開著時讀值會有一點跳動，屬於正常。

可以改的地方：180 改成 90，旋鈕轉到底舵機只轉一半；兩端對調（180、0）讓方向相反。

### 11-ultrasonic-stop — 超音波避障

```
loop:  繪圖 名稱「距離」 數值 = 超音波(Trig 2, Echo 33) 單位 cm
       如果 超音波(Trig 2, Echo 33) < 20
         則 停止馬達 1
         否則 馬達1 Forward 動力 40%
       延遲 100 毫秒
```

距離可以在 **☰ → 開啟獨立 Plotter** 看成曲線。那個 100 毫秒是量測節拍，
不要改成 0；超音波本身也會偶爾跳出離譜的值（打到斜面或太近時），所以這支程式
只適合示範，真要用得加上連續幾次都成立才動作之類的判斷。

### 12-ir-analog — 紅外線類比門檻

```
setup: 停止馬達 全部
loop:  繪圖 名稱「反射值」 數值 = 紅外線(類比) 腳位 32  單位 ADC
       如果 紅外線(類比) 腳位 32 > 2000
         則 停止馬達 1
         否則 馬達1 Forward 動力 40%
       延遲 100 毫秒
```

類比值是 0–4095，能看出遠近而不只是有／沒有。門檻 2000 只是舉例：先打開 Plotter
看「有東西」和「沒東西」各是多少，取兩者中間。越近是越大還是越小依模組而定，
相反的話把 `>` 改成 `<`。

### 13-digital-input — 數位輸入控制舵機

```
setup: 設定腳位 15 模式 INPUT_PULLUP
       舵機1 角度 0
loop:  如果 數位讀取 腳位 15 = 0
         則 舵機1 角度 90
         否則 舵機1 角度 0
       延遲 50 毫秒
```

`digitalRead` 是通用的數位讀取，09 的 `ir_digital` 其實就是它的具名版本。
setup 先把 GPIO 15 設成 **INPUT_PULLUP（內建上拉）**：開關一端接 GPIO 15、一端接 GND，
沒按讀到 1、按下讀到 0，不用外接電阻。沒設上拉的話腳位是純輸入，不接東西時讀值會亂跳。
GPIO 15 是 ESP32 的 strapping 腳，開機時不要按住開關（見 [腳位.md](腳位.md)）。

### 14-led-blink — LED 閃爍

```
setup: 設定腳位 2 模式 OUTPUT
loop:  數位寫入 腳位 2 HIGH
       延遲 500 毫秒
       數位寫入 腳位 2 LOW
       延遲 500 毫秒
```

腳位要先設成 OUTPUT 才能輸出電壓；HIGH 是 3.3V、LOW 是 0V。GPIO 2 是 Wemos D1 R32
的板載 LED，不用接線就能看到。它同時是超音波 TRIG 的預設腳，兩者不要同時接。
外接 LED 一定要串約 220 Ω 的電阻。

### 15-led-fade — LED 亮度

```
setup: 類比寫入 腳位 26 值 0
loop:  類比寫入 腳位 26 值 20 → 延遲 600 → 80 → 延遲 600 → 255 → 延遲 600 → 0 → 延遲 600
```

類比寫入其實是 PWM，0–255 控制亮度。能用的腳位有限（0、2、4、15、18、21、22、26、32、33），
因為要避開馬達與舵機佔用的計時器。值是直接填的數字，不能放表達式。

### 20-plot-compare — 目標與實際轉速

```
setup: 馬達3 轉速 120 RPM
loop:  繪圖 名稱「目標」 數值 = 120  單位 rpm
       延遲 60 毫秒
       繪圖 名稱「實際」 數值 = 馬達3 編碼器 轉速(RPM)  單位 rpm
       延遲 60 毫秒
```

Plotter 依「名稱（單位）」分線：名稱不同就是不同的線，**全部畫在同一張圖、共用縱軸**，
右上的卡片各自顯示最新值。所以想比較的兩個量要放同一個單位。

兩個細節：板子送繪圖資料有 50 毫秒的冷卻（所有名稱共用），兩個繪圖之間
一定要隔 60 毫秒以上，不然第二筆會被丟掉、圖上只剩一條線。Plotter 也不畫負數，
轉速反向時那一段會是空的。轉速閉迴路放在 setup 會一直維持，要按「停止」才會停。

### 21-counter — 計數器

```
setup: 變數 count = 0
loop:  變數 count 增加 1
       顯示訊息 count
       延遲 500 毫秒
```

變數是有名字的盒子；setup 先設 0，每次執行才會從頭數。數字顯示在畫面下方的
訊息列（`message_print` 約 50 毫秒內只送一次，所以要留延遲）。
變數在板子上只存在記憶體，重新送出程式就清掉。

### 22-millis-timer — 不卡住的計時

```
setup: 舵機1 0°、停止馬達、last = 0、up = 0
loop:  如果 (現在毫秒 − last) ≥ 1000
         如果 up = 0 則 舵機1 90°、up = 1
         否則 舵機1 0°、up = 0
         last = 現在毫秒
       如果 Lego按鈕(4) = 0 則 馬達1 Forward 40% 否則 停止馬達 1
       延遲 20 毫秒
```

`delay 1000` 期間程式在睡覺，這時按按鈕沒反應。改成「記下上次時間、每圈看過了多久」，
loop 每圈都跑得很快，按鈕隨時有反應。`millis` 是開機後的毫秒數（約 24 天會繞回 0，
課堂用不到）。按鈕按下讀到 0 還是 1 看接線，同 08。

### 23-random-swing — 隨機擺頭

```
setup: 舵機1 角度 90
loop:  舵機1 角度 = 隨機整數(30 到 150)
       延遲 800 毫秒
```

隨機數包含兩端，每次求值重抽。範圍不要超出舵機的 0–180°。

### 24-procedure — 副程式：抖一下

```
副程式「抖一下」: 舵機1 60° → 延遲 200 → 120° → 延遲 200 → 90°
loop:  呼叫 抖一下 → 延遲 1000 → 呼叫 抖一下 → 延遲 2000
```

副程式定義放在 setup／loop 外面，改一處所有呼叫都跟著變。
副程式不可呼叫自己（直接或間接都不行），也沒有回傳值。
範例的副程式沒有參數。

### 25-range-and — 距離在範圍內才走

```
loop:  如果 (超音波 > 20) 而且 (超音波 < 60)
         則 馬達1 Forward 40%
         否則 停止馬達 1
       延遲 100 毫秒
```

「而且」兩邊都成立才成立；換成「或者」是任一邊成立就成立。
超音波沒回波會讀到 −1，落在範圍外，所以也會停。

### 26-run-once — 只做一次的旗標

```
setup: 停止馬達 全部、done = false
loop:  如果 不是 done
         則 馬達1 Forward 50%、延遲 1500、停止馬達 1、done = true
       延遲 50 毫秒
```

旗標是只有 true／false 的變數。loop 會一直重複，用旗標就能讓某段只做一次。
要再做一次就重新按執行。

### 27-servo-limit — 限制舵機範圍

```
setup: 舵機1 角度 90
loop:  舵機1 角度 = 限制( 對應(類比讀取 32, 0–4095 → 0–180), 30, 150 )
       延遲 50 毫秒
```

`constrain` 把數值夾在下限與上限之間。機構轉到某個角度會卡住時，
用它確保舵機永遠不會被叫去那裡。

### 28-abs-error — 離目標多遠

```
loop:  繪圖 名稱「誤差」 數值 = 絕對值( 超音波 − 30 )  單位 cm
       延遲 100 毫秒
```

超音波減 30 會有正負，絕對值把負號拿掉，只看「差多少」，到 Plotter 看曲線。

### 29-serial-println — 序列輸出

```
setup: n = 0
loop:  n 增加 1
       顯示訊息 n          ← 網頁訊息列
       序列輸出 n          ← USB 序列監視器
       延遲 500 毫秒
```

兩者的去處不同：**顯示訊息**送回「下指令的那個網頁」，手機上看得到；
**序列輸出**只從 USB 線送出，韌體印成 `[PROG] serial_print=數字`，要在電腦開序列監視器
（115200）才看得到，網頁上不會出現。沒接電腦時用顯示訊息就好；
要把資料抓進電腦分析、或網頁沒連線時才用序列輸出。

### 31-patrol — 巡邏車

```
setup: 停止馬達 全部、舵機1 90°
       直到 Lego按鈕(4) = 0 為止：延遲 20
loop:  如果 超音波 < 20
         則 停止馬達 1、舵機1 掃 30° → 150° → 90°（各等一下）
         否則 馬達1 Forward 40%
       延遲 100 毫秒
```

綜合 08（等按鈕）、11（超音波判斷）、02（舵機）。舵機掃描當中程式在等延遲，
超音波暫時不量，掃完下一圈才重新判斷。

## F 系列：對外 I2C（主機與本板互傳數值）

這一系列讓**另一塊主機板**（例如 i2cESP32）透過 I2C 線和本板互傳數字。
一般手機網頁測試用不到，而且**要先做這幾件事才有用**：

1. 燒錄 **`esp32dev_i2c`** 這個 env（`pio run -e esp32dev_i2c --target upload`）。
   預設的 `esp32dev` 沒有 I2C 從機功能，對外功能積木在那裡讀到的永遠是 0、寫出去的值沒人收。
2. 接線：本板 **GPIO 21 = SDA、GPIO 22 = SCL**，再和主機共地。本板的 I2C 位址是 **0x36**。
3. 主機端要登記這個位址（i2cESP32 的 `I2C_STARTUP_ADDRS`）。主機端的儀表板程式
   這份文件沒有驗證過，請以實機為準。
4. 這兩支範例的硬體驗收（見 [i2c_slave_sdd.md](i2c_slave_sdd.md) §9）目前還沒有在實機上做過。

怎麼運作：程式裡用 **宣告對外功能** 積木登記「編號 0–15、數位或類比、可不可以回讀」，
主機就知道本板有哪些功能。之後：

- 主機**設定**一個值 → 本板用 **對外功能 的值** 積木讀出來（數位是 0／1，類比是 −32768～32767）。
- 本板用 **設定對外功能** 積木寫入一個值 → 主機讀得到，但**只有宣告時勾了「可回讀」的功能**才讀得到。
- 名稱、單位、範圍不上 I2C，由主機儀表板自己命名。
- 本板的程式每 10 毫秒跑一圈，回授控制請放在本板的程式裡，不要靠主機透過 I2C 來閉環。

### 41-i2c-param-in — 主機設定舵機角度

```
setup: 宣告對外功能 0  類比  可回讀 ☐
       舵機1 角度 90
loop:  舵機1 角度 = 限制( 對外功能 0 的值, 0, 180 )
       延遲 50 毫秒
```

宣告積木放在 setup，存檔時會被抽到程式最上層，主機一套用就看得到。
主機還沒送過值時，功能 0 的值是 0，所以舵機一開始會轉到 0°。
用「限制」是因為主機可能送出超過 0–180 的數字。

### 42-i2c-report — 回報距離給主機

```
setup: 宣告對外功能 0  類比  可回讀 ☑
loop:  設定對外功能 0 的值為 超音波(Trig 2, Echo 33)
       延遲 100 毫秒
```

「可回讀」一定要勾，不然主機讀不到。超音波沒回波會寫入 −1。

## G 系列：小車副程式

用一台兩輪小車（**左輪 M1、右輪 M2**，沒有編碼器，只用馬達動力）一步一步學副程式。
完整的教學說明、練習題與常見錯誤在 [副程式教學.md](副程式教學.md)，下面是每支的重點。
路線都放在 setup 只跑一遍（56 例外，放在 loop）。**頂層 loop 每 10 毫秒整份跑一圈**，
時間只由 `延遲` 積木決定。

| 範例 | 這一步多學了什麼 |
|------|------------------|
| 51 | 不用副程式：十幾塊積木、前進寫兩次，難讀 |
| 52 | 前進／左轉／右轉／停車四個無參數副程式；主程式像一句話 |
| 53 | `前進(毫秒)`、`左轉(毫秒)`：一個參數，等待與停車包進副程式 |
| 54 | `開車(左輪, 右輪)`：兩個參數，負數倒退，兩輪速度差就是轉向 |
| 55 | `走正方形` = 重複 4 次 { 前進、右轉 }；轉彎時間要在真車上調 |
| 56 | loop 裡 if 超音波 < 20 就 `閃避`，否則 `開車(50, 50)` |

```
副程式 前進(毫秒): 馬達1 Forward 50% → 馬達2 Forward 50% → 延遲 毫秒 → 停止馬達 全部
setup: 前進(1000) → 左轉(400) → 前進(1000)          ← 53
```

要注意的三件事：

- **參數是全域變數**，名字不要和主程式的變數相同；副程式結束後仍保留最後的值。
- **動力放變數時可以是負的**（−100～100，負數倒退）；固定數字的積木只能 0–100。54／56 的 `開車` 靠這點。
- 左右輪若裝反，只改副程式裡的方向（52 的重點）。

## 要新增一支範例

範例 XML 與清單 `data/examples/index.json` 都是**產生出來的**，不要直接手改。
流程是：寫一支原始檔 → 產生 → 離線檢查 → 上傳。

1. **寫原始檔**：在 `tools/examples_src/` 新增 `<id>.cjs`。格式照 `01-motor-pwm.cjs`：
   `meta`（`id` / `name` / `desc` / `hw` / `level` / `series`）、`setup`（陣列）、`loop`（陣列）。
   積木用 `tools/examples_src/_dsl.cjs` 提供的函式寫，例如 `d.pwm(1, 'FORWARD', 50)`、
   `d.delay(1000)`；欄位名與下拉值要和 `data/appBlock.js` 一致。
   想在積木上附 💬 說明，就用 `d.note('文字', 積木)` 包起來。
2. **產生**：`node tools/gen_examples.cjs`。會寫出 `data/examples/<id>.xml`，並更新
   `index.json`（含抽屜分組用的 `series`，以及每支用到的積木清單 `blocks`）。
3. **檢查**：`node tests/check_examples.cjs`。會檢查積木與欄位名稱、下拉值、數值插槽有沒有空的、
   整支能不能變成合法 PROG JSON（含 8 層巢狀上限），以及積木覆蓋率。
4. **上傳**：`pio run --target uploadfs`（只改 `data/` 不用重燒韌體），再到手機上開一次確認。

### id 編號

編號大致依系列排，抽屜會依系列分組（系列以 `meta.series` 為準）：

| 編號 | 系列 | 目前的範例 |
|------|------|------------|
| `01`–`04` | A 動起來 | 01–04 |
| `05`–`07` | B 角度 | 05–07（雖然也是 `0x`，但屬於 B，不是 A） |
| `08`–`19` | C 感測與腳位 | 08–15 |
| `20`–`30` | D 邏輯資料 | 20–29 |
| `31`–`40` | E 整合 | 31 |
| `41`–`49` | F 對外 I2C | 41–42 |

id 只能用英數與 `-`、`_`，`meta.series` 要填對應的字母（A–F）。

### 幾條規則

- **手改會被擋下來**：`node tools/gen_examples.cjs --check` 會比對 `data/examples/` 與原始檔產生的結果，
  只要 XML 或 `index.json` 有一個字不一樣就失敗（`check_examples.cjs` 一開始也會跑這一步）。
  要改內容就改 `tools/examples_src/` 再重新產生。
- **新積木要有範例**：`check_examples.cjs` 的覆蓋率檢查已經開啟（`REQUIRE_FULL_COVERAGE`）。
  新增一種積木後，要嘛補一支範例用到它，要嘛在該檔的 `EXEMPT` 寫上不需要範例的理由，否則測試不過。
- **描述 `desc` 在 120 字以內**，抽屜裡才顯示得完。
- 單支 XML 不超過 8 KB，全部範例加起來不超過 128 KB（LittleFS 空間）。

### 先在積木頁試，再翻成 DSL

要試一段積木，最快的方式還是在積木頁拉好程式，按 **⬇️ 下載到本機** 看它的結構，
再照上面的格式翻寫成 `tools/examples_src/<id>.cjs`。下載的 `.xml` 不要直接放進 `data/examples/`，
那樣 `--check` 會失敗。

不要在範例裡放已刪除的舊「馬達」「舵機」積木 —— 測試會直接擋下來（那種檔案在
2026-10-09 之後根本載不進工作區）。
